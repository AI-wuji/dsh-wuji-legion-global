## 一、角色维度遗漏（3 处）

### 遗漏1：综合官定位
- **数据背书**：[openspec-agents（状态机多智能体协作）](https://github.com/gmf520/openspec-agents) —— 主调度器 + 8 专职子 agent + 严格阶段跃迁规则，证明"协调者"有成熟范式。
- 综合官 = 会审档（用户要求多堂会审）时把多职权合在一次调用的协调者；MoE 档不需要。参考 openspec-agents 的"主调度器协调多子 agent"模式。

### 遗漏2：进化主帅 vs 能力主帅层级
- **数据背书**：[AgenticStateMachines](https://github.com/adamterlson/AgenticStateMachines) —— 状态机定义区分不同 agentic 模式（工具使用/反思/协作/人机协作等），证明"元层 vs 执行层"分层有成熟范式。
- 进化主帅 = 宿主层元主帅（管进化治理），能力主帅 = 执行层域主帅（管执行），不平行。

### 遗漏3：通讯员（普通军人岗位）
- **数据背书**：[Anemoi（半中心化多 agent，A2A 通信 MCP）](https://huggingface.co/papers/2508.17068)（NeurIPS 2025）+ [AI-Agent-MCP-Server（agent 间通信）](https://github.com/sairamaraov/AI-Agent-MCP-Server)
- 通讯员 = 主帅域内"信息传递/状态上报"岗，参考 A2A（Agent-to-Agent）通信协议——是流水线实时反馈的执行者。

## 二、机制维度遗漏（4 处）

### 遗漏4：能力路由实现
- **数据背书**：[vLLM Semantic Router](https://github.com/vllm-project/semantic-router)（官方，有 benchmark）+ [Arch-Router-1.5B](https://huggingface.co/ArtusDev/katanemo_Arch-Router-1.5B-EXL3/raw/2.5bpw_H6/README.md)（小模型路由）
- 路由 = 确定性触发词优先 + 语义检索兜底（semantic-router）+ 未命中才问用户。

### 遗漏5：技能生命周期状态推进
- **数据背书**：[AgenticStateMachines](https://github.com/adamterlson/AgenticStateMachines)（状态机模式）+ [flowguard](https://github.com/leakingMemo/flowguard)（状态机引擎）+ [maestro STATES](https://github.com/SnapdragonPartners/maestro)
- 生命周期状态机（known→callable→behavior-verified→primary），进化主帅是推进者，每次推进带证据句柄。

### 遗漏6：记忆遗忘机制
- **数据背书**：[memwatch（记忆过期自动失效）](https://github.com/kresnapandu/memwatch) + [AI-Memory（艾宾浩斯遗忘曲线）](https://github.com/xwj-vic/AI-Memory) + [agent-memory-mcp（TTL 记忆）](https://github.com/Rumblingb/agent-memory-mcp)
- 记忆条目带 TTL + 失效条件 + 替代关系；参考艾宾浩斯遗忘曲线（久不用的记忆自然衰减）。

### 遗漏7：多用户/多会话
- **数据背书**：[Salesforce 多租户 Agent 平台（7K+ 会话无串扰）](https://engineering.salesforce.com/building-a-multi-tenant-ai-agent-platform-handling-7k-sessions-without-cross-team-interference/) + [微软 agent-framework 每用户会话存储隔离](https://github.com/microsoft/agent-framework/blob/7ca73c0645ad057c986cc7072d4a2d9e3f1cc6f3/docs/decisions/0031-hosted-per-user-session-storage-isolation.md)
- 宿主层服务全局共享，会话层按用户隔离；参考 Salesforce 的租户隔离 + 微软的 per-user 存储隔离。

## 三、横向维度遗漏（3 处）

### 遗漏8：降级/降载
- **数据背书**：[agent-armor（熔断/隔舱/重试/模型回退）](https://github.com/Ismail-2001/agent-armor) + [graceful-degradation-protocol](https://skills.rest/skill/graceful-degradation-protocol) + [agentpause（限流前优雅暂停）](https://github.com/Champoleello/agentpause)
- 高压时降档/降并发/降功能；参考 agent-armor 的 bulkheads（隔舱）+ 熔断 + 模型回退。

### 遗漏9：任务优先级/排队
- **数据背书**：[agentic-dev-orchestrator（WSJF 加权最短作业优先排序）](https://github.com/danieleschmidt/agentic-dev-orchestrator) + [task-agent（优先任务队列）](https://pypi.org/project/task-agent/0.1.248/) + [long-run-agent（7 状态管理）](https://github.com/hotjp/long-run-agent)
- 优先级排序参考 WSJF（加权最短作业优先）；队列参考 task-agent。

### 遗漏10：回滚版本历史保留
- **数据背书**：[dsh-continual-evolve（版本化可回滚）](https://github.com/ZK-Andy/dsh-continual-evolve)（DSH 官方生态，之前已搜）+ [agent-rollback（修改前检查点）](https://www.npmjs.com/package/agent-rollback)
- 版本历史保留 + 检查点回滚；参考 continual-evolve 的"版本化+可回滚"。

## 四、关键结论

1. **10 处遗漏全部有数据背书**，不再臆想。
2. **最意外的发现**：
   - Salesforce 的 7K+ 会话多租户隔离（遗漏7）——真实工业级多用户方案
   - 艾宾浩斯遗忘曲线（遗漏6）——记忆遗忘有心理学依据
   - WSJF 优先级排序（遗漏9）——项目管理成熟方法
   - A2A agent 间通信协议（遗漏3）——通讯员岗位有标准协议

3. **方法改进**：这次复查的每一个"补充"，都先搜索、再写结论——"搜索 → 数据 → 结论"，而不是"推断 → 结论"。

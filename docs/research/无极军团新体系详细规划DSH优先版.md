# 无极军团 · 新体系详细规划（DSH 优先版）

> 版本：v1.0
> 日期：2026-08-15
> 平台：DeepSeek Harness（DSH）
> 原则：**一切优先复用 DSH 原生能力，不重造轮子**；名字用无极建制；外部项目只学方法不借名字。
> 本文整合了全部讨论成果（流水线执行、模型分级、表格图谱、能力进化、独立官员、三大痛点解法）与全网调研结论。

---

## 一、总定位与初心

**两句话**：
1. 让不懂技术的小白用大白话提要求，系统自动调齐能力把事办成，用户无感；
2. 同类能力通过查漏补缺、取长补短**重生**成更强的新能力，越用越强。

**核心约束**：全程优先用 DSH 现成机制（子代理、工作流、记忆账本、动态插件、MCP 客户端），自己只补 DSH 没有的"组织调度"这层。

---

## 二、组织架构（三级建制）

```
军团级
├── 阿极        —— 用户接口（收集需求、澄清、汇报）
├── 参谋部      —— 中枢（拆任务、调度、实时监控反馈）
└── 独立官员    —— 审查顾问（白帽/质检/审计/合规/根因/性能/综合）

师团级
└── 各级主帅    —— 能力域负责人（内容/视觉/开发/情报/进化/安全…）

普通军人岗位
└── 通讯员等    —— 挂在主帅下，干单一职能的活
```

**权限边界（三层，强制）**：
```
官员只能建议 → 用户决定 → 阿极执行
```
- 独立官员**只有建议权、零修改权**（不写任何表、不派发、不否决、不裁决完成）。
- 官员建议须经"用户采纳 + 阿极转写"两步才生效，缺一即越权。

## 三、核心运行机制

### 3.1 流水线执行（不是讨论会）

**核心形态**：参谋部配发 → 多个子 agent 并行 → 各干各的 → 实时反馈 → 汇总推进。

```
阿极收集需求（填需求表）
  → 参谋部把需求翻译成任务分配表（甘特图式）
  → 参谋部配发任务给多个子 agent
  → 子 agent 并行执行，各自只拿自己那份任务的说明
       · 打螺丝的只知道打螺丝，装箱的只知道装箱，不知道全局
  → 参谋部实时接收反馈：
       · 成功的 → 汇总
       · 失败的 → 再派一个，或换个角度重新派
  → 有依赖的串行（上阶段完成才下阶段），无依赖的并行
  → 汇总成功结果，推进下一步
```

**DSH 落点**：子 agent = DSH `subagent`；并行 = DSH `workflow` 的 `parallel()` / `pipeline()`；实时反馈 = 后台 `jobs` + 完成通知。

**关键纪律（白帽钉死，防"慢"复发）**：
1. **失败重派有熔断上限**：同一子任务最多换 3 个角度（策略），累计 5 次无进展就停，把失败+证据交用户决定。**不允许无限重派**（否则又回到"简单问题拖一天"）。
2. **子 agent 不互相开会**：默认各干各的，禁止多 agent 讨论会拖慢任务；只有用户明确要求"多堂会审"时才允许官员开临时会（会审档）。

### 3.2 模型分级（按难度配智力，省费用省时间）

| 角色 | 模型档位 | 理由 |
|---|---|---|
| **阿极** | 便宜快速档（如 DeepSeek Flash / GPT5.6-Luna） | 收集需求对话多，但不需要高推理；便宜的快 |
| **参谋部** | 高智商档 | 拆任务、调度、判断失败处理——最需要动脑 |
| **子 agent** | 按任务难度分档 | 简单活（格式转换/检索）用便宜快速；难活（架构/复杂推理）才上强模型 |

**白帽钉死的关键原则**：**分级按"难度匹配"，不是"便宜优先"**。避免两个极端：
- "大炮打蚊子"（简单活上强模型，贵且慢）；
- "玩具车拉重货"（难活上便宜模型，返工一次比直接用强模型还贵还慢）。

**DSH 落点**：DSH 支持不同 agent/子代理配不同模型（`subagent` 可指定 model/provider；`agentDefaultModel` 管默认）。阿极 = 会话默认模型设为便宜档；参谋部调度逻辑若需要独立高智商，可用独立子代理承担；子 agent 按任务在派发时指定模型。

> 备注：单模型环境（当前 deepseek-v4-flash）下，模型分级先作为**能力契约**存在（哪个岗位将来接哪个档的模型），实际切模型待 DSH 配置到多模型后即生效。

### 3.3 表格图谱（框架 + 当前项，稀疏投影）

**核心思想（您最初的设想，完全正确）**：每个岗位一张表，每次只带"**整张表的标题框架 + 当前正在处理的那一项的完整内容**"。

| 岗位 | 表 | 内容 |
|---|---|---|
| 阿极 | 用户需求表 | 用户想要什么/不要什么/约束/验收 |
| 参谋部 | 任务分配表 | 什么任务给了谁、要求、输出返回格式、失败处理（甘特图式） |
| 各主帅/岗位 | 各自的工作表 | 自己职责域的状态 |

**上下文调度规则**：
1. 每次交流修改，只带：**表框架（所有标题/骨架）+ 当前项全文 + 版本指针 + 当前消息**。
2. 例：10 项的表，正在聊第 2 项，上下文 = 10 个标题 + 第 2 项全文。
3. **可继续下潜**：第 2 项还能拆小项，钻到更小颗粒。
4. **允许跨单元显式引用**：有些项互相关联，需要时可以把关联项带进来（如聊第 2 项需要看第 5 项的约束）。**但必须显式、有界**——注明"为什么需要它"，一次最多带关联的几项，够用就停，不追着关联链无限扩散。

**参谋部的任务分配表（甘特图式）**，每行记录：
```
任务ID · 分给谁 · 具体要求 · 输入 · 输出格式 · 返回格式
· 依赖（哪些任务必须先完成）· 失败处理（重试/换角度/上报）
· 状态（待派/执行中/成功/失败）· 证据句柄
```
- 无依赖 → 并行；有依赖 → 串行（上阶段完成才下阶段）。
- 全部有据可查（谁干的、什么时候、结果证据）。

**DSH 落点（这是最关键的一条）**：DSH 原生有 `sessionProjections` 服务（投影单元表 + 事件驱动 + 检查点/恢复/持久化），goal、todo、token 计量都在用它。**我们直接注册三张表的投影单元（需求表/分配表/官员建议表），每次模型调用通过 `systemPrompt.variable()` 只注入"框架 + 当前项"**——不需要自造图谱存储。完整历史留 DSH 会话持久化做冷证据。

### 3.4 能力进化（自动进化闭环，初心②）

**进化 = 重生**：不是叠加（父代并列）、不是替换（只留最强），而是取长补短合成新物种。

**自动进化闭环（Hermes 机制 + 无极审核）**：
```
打赢一场漂亮仗（成功任务）
  → 独立官员（只建议）点评：哪些招好使、哪些报错
  → 参谋部拍板：把可复用套路提纯成"新技能草稿"
  → 进化主帅审查：互补矩阵（父代优点/缺点/新决策结构）+ 同 fixture 对照
  → 对照不降级 → 版本化入库（可回滚）
  → 下次同类任务命中自动装配
```

**技能格式**（对齐 Claude/Codex 双生态，DSH 直接兼容）：
```
技能/
├── SKILL.md        # 薄入口：名字/描述/触发条件/边界 + 关键步骤
├── references/     # 详细步骤/模板/资产，用到才展开
└── verify.*        # 行为探针：真实产物 + SHA-256 证据
```

**进化的关键机制（调研成果整合）**：
- 技能四元组：`{触发条件, 描述, 执行过程, 反思}`（AutoSkill）
- 三阶段流水线：归纳（提炼新技能）→ 组合（融合重生）→ 泛化（迁移新场景）
- 分层合并：融合时去重、取长补短（Trace2Skill）
- 验证信号自进化：验证标准本身也随经验进化，逐步摆脱每次人工验证（OpenSkill）
- 单模型自我蒸馏：从成功/失败会话提炼"教训"而非答案（SEED，适配单模型环境）
- 版本化回滚：进化先过验证再落盘，失败可回滚旧版

**DSH 落点**：新技能 = 一个 skill 目录（或 cordis 动态插件）；进化提案 = `cordis_define` 定义新包；验证 = pwsh 跑探针；回滚 = cordis 插件版本回退。**融合对比**用四臂 A/B（融合/父A/父B/基线），不降级才保留。

### 3.5 独立官员（防迎合 + 防融合退化）

**执行形态（MoE 化）**：默认**一个子 agent 承载全部职权**，每次只激活一个（启动成本≈0）；用户明确要求"多堂会审"时才开多个隔离子 agent。

**触发**：契约自动、无人工干预（失败→根因官；高风险→保卫科；发布→审计/合规）。

**白帽（最核心，防迎合）**：
- 命名源流：宪兵（白钢盔），执法纠错不徇私，**反驳而非迎合**。
- **默认开启、默认不独立启动**：反驳义务是人格层机制（写进阿极 persona："方案确认前必须输出假设/反例/风险/备选，不允许迎合"），0 额外成本。
- 防纯抬杠：怀疑派 + Steelman（先替用户把想法最合理的版本说出来，再攻击）。
- 用户确认后白帽退出热路径。

**权限**：只有建议权、零修改权（见 §二）。

**DSH 落点**：官员 = 一个子 agent（MoE 档）内的职权模板切换，或 `subagents` 隔离审查席（会审档）；白帽 = preset persona 强制义务。

### 3.6 记忆系统（三层记忆，治上下文膨胀）

**三层记忆（Hermes 机制，映射到 DSH）**：
| 层 | 内容 | DSH 落点 |
|---|---|---|
| core（长期稳定） | 用户身份/偏好 + 军团宪法 | 持久化文件（USER.md / 军团宪法） |
| working（当前会话） | 正在干的事 | 当前会话上下文 |
| episodic（历史经验） | 以前干过的活的摘要 | `sessionProjections` 持久化历史任务库 |

- 会话结束**压缩蒸馏成记忆条目**，不全量保存；读取按需检索。
- **有界记忆**：只写回被证明有用的，没用的不存。
- 上下文审计：定期统计哪些内容占 token 多，精简（借鉴 dsh-context-doctor）。

## 四、三大痛点解法总表

| 痛点 | 解法 | DSH 落点 |
|---|---|---|
| **慢** | 流水线并行 + 直道优先（简单任务不过参谋部）+ 前置限制（规矩立开工前）+ 熔断（失败重派有上限） | subagent/workflow 并行 · 快慢路由 · goal 预算 · 调用指纹熔断 |
| **融合更差** | 重生（互补矩阵）+ 四臂 A/B 不降级才保留 + 薄入口渐进披露（选项少选择快） | cordis_define 新包 · 探针验证 · skill 目录分层 |
| **上下文大** | 表格框架+当前项（稀疏投影）+ 三层记忆压缩 + 用到才翻 | sessionProjections + systemPrompt.variable 注入 + 渐进披露 |

| 阶段 | 干什么 | DSH 优先实现 | 验收 |

## 六、验收标准（三大痛点是否真解决）

| 痛点 | 指标 |
|---|---|
| 慢 | 简单任务直道 2-3s；无依赖分支真并行；失败重派 ≤3 角度/5 次即熔断；后置验证仅剩高危一次性门禁 |
| 融合差 | 每次融合过四臂 A/B 任一父代维度不降级；技能库只挂元数据（渐进披露）；选项增多时选择不退化 |
| 上下文大 | 每次调用只带"表框架+当前项"（sessionProjections 生效可证）；未选中技能零 token；上下文审计 token 受控 |

---

## 七、总结

新无极军团 = **流水线并行（快）+ 模型分级（省）+ 表格稀疏投影（上下文小）+ 能力进化重生（越用越强）+ 白帽反驳（防迎合）**，全部构建在 DSH 原生能力上（subagent/workflow/goal/jobs/sessionProjections/cordis 动态插件），自己只补"组织调度 + 进化治理"这一层。名字全用无极建制，外部只学方法不借名字。

**最优先两步**：P0（技能库 + 三张表投影 + 阿极 persona）→ P1（参谋部流水线调度）。这两步纯增量、不动现有技能、风险最低。

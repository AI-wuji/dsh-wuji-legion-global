# 无极军团 · 架构下沉方案（DSH 到底能沉多低）

> 版本：v1.0
> 日期：2026-08-15
> 性质：对规划的根本性重新定位——之前把无极军团做成了"DSH 之上的一层应用"，现在下沉到"DSH 内部的系统级插件组合"。
> 依据：运行时 Inspect 实测 DSH 底层服务 + 全网调研（官方架构文档、cordis 入门、自进化蓝图、社区拆解）。

---

## 一、核心判断（您是对的，规划需要下沉）

**之前规划的定位错误**：把无极军团当成了"浮在 DSH 上面的应用"——用 persona 文字模拟阿极、用 skill 文件模拟主帅、用抽象概念模拟门禁。

**DSH 的正确玩法**：DSH 是"**万物皆插件，连最底层都是插件**"（官方：host composition 持有所有注册表，agent preset 是一层会话贡献）。**无极军团不应该浮在上面，而应该是一套 Cordis 插件组合，深深嵌进 DSH 的宿主层和会话层。**

**甚至更深**：DSH 官方已发布"**自进化蓝图**"和"**让 Agent 在运行中改写自己**"的论文——DSH 的设计目标就是"agent 能在运行时通过插件机制改写自己的插件"。这和无极军团的"进化重生"初心是**同一个东西**——我们不该自造进化机制，而该**用 DSH 原生的自进化能力**。

---

## 二、实测：DSH 底层有哪些"钩子"（能沉多低的依据）

我通过 Inspect 直接查了宿主服务，这些是**之前规划完全没用够的底层能力**：

### 2.1 工具层（tools 服务）——能沉到"运行时注册/守卫/限制工具"

| 底层能力 | 实测方法 | 无极军团对应 |
|---|---|---|
| 运行时注册工具 | `tools.register(definition)` | **每个能力 = 一个注册进 tools 的工具**，不是 skill 文件 |
| 工具守卫（能 deny） | `tools.guard(guard)` | **保卫科 = 注册一个 tool guard**，真正在执行前拦截 |
| 工具范围限制 | `tools.restrict(filter)` | **子 agent 最小权限 = restrict 它的工具范围** |
| 作用域隔离 | scoped registrations shadow globals | **主帅/岗位 = 各自 scope 的工具** |

### 2.2 子代理层（subagents 服务）——能沉到"自定义 provider + 实时控制"

| 底层能力 | 实测方法 | 无极军团对应 |
|---|---|---|
| 自定义子代理提供者 | `subagents.registerProvider(provider)` | **各级主帅/普通岗位 = 各自注册的 provider** |
| 可延续子代理 | `startContinuable` | **常驻的参谋部/官员 = continuable 子代理** |
| 追加指令 | `followup` | **参谋部实时追加指令给子 agent** |
| 打断 | `interrupt` | **参谋部实时打断子 agent** |
| 上报 | `reportFrom` | **子 agent 向参谋部上报** |

### 2.3 提示词层（systemPrompt 服务）——能沉到"每次调用注入"

| 底层能力 | 实测方法 | 无极军团对应 |
|---|---|---|
| 动态变量注入 | `systemPrompt.variable(name, provider)` | **表格投影 = variable，每次调用注入当前项** |
| 有序段落 | `systemPrompt.section()` | **军团宪法/白帽义务 = 有序 section** |
| 工具 schema 提供者 | `systemPrompt.tools(provider)` | **按需呈现工具 = tools provider** |
| 动态上下文 | `systemPrompt.context()` | 运行时上下文 |

### 2.4 模型层（llm 服务）——能沉到"自定义模型适配器"

| 底层能力 | 实测方法 | 无极军团对应 |
|---|---|---|
| 注册模型适配器 | `llm.registerAdapter` | **模型分级 = 注册多档 adapter** |
| 流式调用拦截 | `llm/stream` waterfall | **白帽/审计 = 拦截每次模型调用** |
| 模型发现 | `registerModelDiscovery` | **档位映射 = 动态发现可用模型** |

### 2.5 事件层（Event）——能沉到"监听每个底层时刻"

| 底层事件 | 模式 | 无极军团对应 |
|---|---|---|
| `agent/pre-step` | waterfall | **白帽 = 每步前注入反驳义务** |
| `agent/request` | waterfall | **参谋部 = 每步前改请求配置** |
| `system-prompt/assemble` | waterfall | **表格投影 = 装配时注入** |
| `tools/pre-execute` | waterfall | **保卫科 = 工具执行前拦截** |
| `session/event` | emit | **记忆 = 监听每个会话事件** |

## 三、结论：能沉到多低？

**DSH 的"地板"不是 skill 文件，不是 persona 文字，而是 Cordis 的插件内核本身**——host composition（宿主组合）持有所有注册表，一个插件可以在宿主层：
1. **注册服务**（成为别的插件能依赖的服务）
2. **监听/拦截事件**（agent 每步、工具每次执行、模型每次调用）
3. **注册工具/子代理/技能**（成为 agent 能调用的能力）
4. **动态改写自己**（cordis_define/run/stop/undefine + 官方自进化蓝图）

**这意味着无极军团可以沉到：**
- **阿极** = 不是 persona 文字，而是一个**宿主层插件**，用 `agent/request` 和 `systemPrompt.section` 真正控制会话
- **白帽** = 不是"写进 persona 的提醒"，而是一个**监听 `agent/pre-step` 的插件**，在每次模型思考前强制注入反驳视角
- **参谋部** = 不是一个 skill，而是一个**注册 subagent provider 的宿主插件**，真正能 start/followup/interrupt 子 agent
- **保卫科** = 不是抽象门禁，而是**注册 `tools.guard()` 的插件**，真正 deny 危险工具调用
- **表格图谱** = 不是自造存储，而是**注册 `sessionProjections` 投影单元 + `systemPrompt.variable()` 注入**
- **进化主帅** = 不是 workflow，而是**监听事件 + 动态 cordis_define 新插件**（DSH 官方自进化蓝图就是这个）

## 四、下沉方案：无极军团 = 一套 Cordis 插件组合

```
宿主组合（host composition，DSH 底层，跨会话共享）
├── wuji-staff（参谋部）——宿主插件：注册 subagents provider + 调度服务
├── wuji-officers（独立官员）——宿主插件：监听 agent/pre-step（白帽）+ 注册审查 subagents
├── wuji-gate（保卫科）——宿主插件：注册 tools.guard() + 监听 tools/pre-execute
├── wuji-projection（表格图谱）——宿主插件：注册 sessionProjections 单元 + systemPrompt.variable
├── wuji-evolution（进化主帅）——宿主插件：监听 tools/result + 动态 cordis_define
├── wuji-registry（技能库）——宿主服务：skills.registerProvider + 能力注册表
└── wuji-memory（记忆）——宿主插件：sessionProjections 记忆单元

会话预设（agent preset，每个会话挂载）
├── 阿极 persona（会话对话层，用户接口）
├── 白帽反驳义务（systemPrompt.section）
└── 军团宪法（稳定前缀 section）
```

**每个角色都是真正的 Cordis 插件**，不是 persona 文字或 skill 文件——它们能注册服务、监听事件、拦截调用、动态改写自己。

## 六、关于"另一个更先进的 harness"

您说"哪怕是另一个更先进的 harness"——这个判断也对，但要澄清：

**不需要另起炉灶。** DSH 本身就是为"自进化"设计的（官方自进化蓝图 + 让 Agent 改写自己的论文）。无极军团要做的不是"再造一个 harness"，而是**作为 DSH 上的一套系统级插件组合，把 DSH 的底层能力全部用起来**——这比另起炉灶更优：站在 DSH 的肩膀上，享受它的所有原生能力（子代理/记忆/模型路由/工具/自进化），同时通过插件把它"改造成无极军团"。

如果将来 DSH 的某个底层能力不够，无极军团可以作为插件**扩展它**（因为插件能注册服务、能改事件），而不是重造。

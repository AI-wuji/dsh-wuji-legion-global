# 无极军团 · 全环节可借鉴清单（逐环节对应调研）

> 版本：v1.0
> 日期：2026-08-15
> 性质：按规划各环节逐一对应搜索可借鉴项。标注"已借鉴/新增/待证"。所有外部项目只作方法出处，不进入无极命名。

## 一、阿极环节（需求收集、澄清、意图理解）

| 可借鉴 | 机制 | 融合点 | 裁决 |
|---|---|---|---|
| [Learning to Clarify（Google，ICLR'25）](https://research.google/blog/learning-to-clarify-multi-turn-conversations-with-action-based-contrastive-self-training/) | 学习"何时该澄清、何时该直接做"——避免过度提问，也避免瞎猜 | **阿极澄清策略**：只在需求有歧义且影响结果时才问，能推断的不问（呼应"源头堵死+精简"） | **融合提案** |
| [ClarifyMT-Bench](https://www.semanticscholar.org/paper/59b355d840e89c4df094093553f38897399b7786) | 多轮澄清的评测与改进 | 阿极澄清质量的评测标准 | 仅借鉴 |
| [MAC（NeurIPS'25）](https://neurips.cc/virtual/2025/loc/san-diego/127976) | 多 agent 交互式用户澄清框架 | 多 agent 协同澄清参考 | 仅借鉴 |
| [AskToAct](https://aclanthology.org/2025.emnlp-main.682/) | 自我纠正式澄清增强工具使用 | 阿极澄清后自动纠正工具调用 | 仅借鉴 |

**关键**：阿极澄清的核心是"**能推断的不问、有歧义才问、问一次问到位**"——避免"过度澄清"拖慢，也避免"瞎猜"返工。

## 二、参谋部环节（任务分解、规划）

| 可借鉴 | 机制 | 融合点 | 裁决 |
|---|---|---|---|
| [Agent-Oriented Planning（ICLR'25）](https://proceedings.iclr.cc/paper_files/paper/2025/hash/31610e68fe41a62e460e044216a10766-Abstract-Conference.html) | 面向 agent 的规划：把任务分解为 agent 可执行的子任务 | 参谋部拆解的依据：按"子 agent 能否独立执行"拆 | **融合提案** |
| [CART（可追溯零样本规划 + 自适应重规划）](https://www.sciencedirect.com/science/article/abs/pii/S0950705125022233) | 零样本规划 + 执行中自适应重规划 | 参谋部在任务执行中根据反馈自适应调整计划（不是死板执行） | **融合提案** |
| [GMATP-LLM（多 agent 动态规划）](https://pure.bit.edu.cn/en/publications/gmatp-llm-a-general-multi-agent-task-dynamic-planning-method-usin/) | 通用多 agent 任务动态规划 | 多 agent 动态调度参考 | 仅借鉴 |
| [Planning with Multi-Constraints](https://aclanthology.org/2025.coling-main.672/) | 多约束协同规划 | 多约束任务（如 PPT 又要美观又要数据准确）的拆解 | 仅借鉴 |

**关键**：参谋部拆解的核心是"**按子 agent 能否独立执行来拆**"，且执行中**自适应重规划**（不是拆完就死板执行）。

## 三、流水线环节（失败重试、换角度）

| 可借鉴 | 机制 | 融合点 | 裁决 |
|---|---|---|---|
| [LiteLLM Router fallback + retry/cooldown](https://github.com/openai/openai-agents-python/issues/813) | 模型失败自动回退 + 重试 + 冷却 | 失败重派的工程实现（fallback + cooldown 防雪崩） | **融合提案** |
| [SAGE（置信度验证的多模型编排）](https://github.com/saim-x/SAGE) | 基于置信度的多模型工作流验证 | 失败/低置信时换模型重试的依据 | 仅借鉴 |
| [LangChain model_fallback middleware](https://github.com/langchain-ai/langchain/blob/0e97e85a/libs/langchain_v1/langchain/agents/middleware/model_fallback.py) | 模型回退中间件 | 模型级 fallback 的工程模式 | 仅借鉴 |

**关键**：失败重派要加"**冷却（cooldown）**"防雪崩——不是无脑立即重试，而是短暂冷却后再试；换角度要基于"置信度/错误类型"判断，不是盲换。

## 四、进化主帅环节（能力互补、蒸馏评估）

| 可借鉴 | 机制 | 融合点 | 裁决 |
|---|---|---|---|
| [Knowledge Fusion via Modular SkillPacks（ICLR'26）](https://openreview.net/forum?id=wJtD28wGV1) | 模块化技能包融合大模型知识 | **"重生"的组合机制**：模块化包 + 组合接口 = 融合新能力的结构（之前已列为融合提案，这里再次确认） | **融合提案** |
| [Knowledge Grafting（知识嫁接）](https://huggingface.co/papers/2505.18502) | 知识嫁接：把新知识接入已有模型 | **能力"嫁接"**：把某技能的能力嫁接到另一技能上（取长补短的另一种形式） | **融合提案** |
| [Fusing LLM Capabilities with Routing Data](https://hub.baai.ac.cn/paper/0a6683f6-59b2-4763-9b9a-1565e0fdb99c) | 用路由数据融合能力 | 融合时参考真实路由数据（哪些能力常一起用） | 仅借鉴 |

**关键**：进化主帅的"重生"有学术支撑——SkillPacks（模块化组合）+ Knowledge Grafting（嫁接）正是"取长补短"的两种学术形态。

## 五、记忆环节（混合检索）

| 可借鉴 | 机制 | 融合点 | 裁决 |
|---|---|---|---|
| [khora（混合检索记忆库）](https://pypi.org/project/khora/0.17.1/) | 文档 + 向量 + 图关系的混合检索 | 三层记忆的检索方式：不同记忆类型用不同检索（向量/关键词/图） | **融合提案** |
| [MemoriesDB（时序-语义-关系记忆库）](https://ar5iv.labs.arxiv.org/html/2511.06179) | 把经验建模为"时序-语义表面"的图 | episodic 记忆的结构：经验按时间+语义+关系组织 | 仅借鉴 |
| [genesis-memory（Qdrant 向量 + SQLite FTS5）](https://github.com/WingedGuardian/genesis-memory) | 向量 + 全文检索混合 + 多因子评分 | 混合检索的工程实现 | 仅借鉴 |

**关键**：记忆检索要**混合**（向量找语义相似、关键词找精确匹配、图找关系），不是单一向量检索。

## 六、子 agent 任务契约环节（上下文注入）

| 可借鉴 | 机制 | 融合点 | 裁决 |
|---|---|---|---|
| [SubAgent 设计三铁律（状态隔离/原子通信/契约化错误处理）](https://blog.csdn.net/weixin_34233974/article/details/162648709) | 状态隔离 + 原子通信 + 契约化错误处理 | **子 agent 三铁律**：①状态隔离（各拿各的上下文）②原子通信（只传结构化结果）③契约化错误处理（错误按约定格式返回） | **融合提案** |
| [Codex subagent 本质（可编排协作单元 + config 契约）](https://blog.csdn.net/weixin_30861797/article/details/95159431) | 子 agent 是"可编排协作单元"，用 config 定义契约 | 子 agent 的任务契约用配置定义（输入/输出/边界） | 仅借鉴 |

**关键**：子 agent 的任务契约要**三铁律**——状态隔离（呼应"打螺丝的只知打螺丝"）、原子通信（只传结构化结果）、契约化错误处理（失败按约定格式返回，便于参谋部判断重试/换角度）。

## 七、本轮的增量建议（并入规划）

1. **阿极澄清**：能推断的不问、有歧义才问、问一次问到位（Learning to Clarify）。
2. **参谋部规划**：按"子 agent 能否独立执行"拆解 + 执行中自适应重规划（Agent-Oriented Planning + CART）。
3. **失败重派加冷却**：cooldown 防雪崩，换角度基于置信度/错误类型（LiteLLM Router）。
4. **进化重生有学术形态**：SkillPacks（模块化组合）+ Knowledge Grafting（嫁接）。
5. **记忆混合检索**：向量+关键词+图，不同记忆类型用不同检索（khora）。
6. **子 agent 三铁律**：状态隔离 + 原子通信 + 契约化错误处理。

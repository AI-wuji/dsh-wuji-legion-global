# 无极军团 · 第三轮调研报告（代码正确度、精简、省 token）

> 版本：v1.0
> 日期：2026-08-15
> 性质：第三轮调研，聚焦用户新提的三个点：①代码开发正确度（不产生屎山/bug）；②大神能力 skill；③省 token 命中率。裁决沿用 E6 四态，外部项目只作方法出处、不进入无极命名。

**关键结论**：
- **ponytail + addyosmani + superpowers 三件套**正好覆盖您说的三个要求：精简（ponytail：能删就删/能用一行不用两行）+ 纪律（addyosmani：22 个生产级 skill）+ 正确度（superpowers：TDD/系统化调试/需求拷打）。
- 融合方向：蒸馏成无极军团"**开发主帅**"的内核，作为**默认思维模式**（常驻，不是按需调用），让每个写代码的子 agent 天生就规范、精简、少 bug。

## 三、省 token / 提升命中率（对应"提升命中率节省 token"）

| 项目 | 机制 | 融合点 | 裁决 |
|---|---|---|---|
| [Prompt caching（前缀缓存）](https://spring.io/blog/2025/10/27/spring-ai-anthropic-prompt-caching-blog) | 复用共享前缀段，减少 prefill 延迟 | **稳定前缀设计**：军团宪法/常驻工具/skill 目录卡放最前，命中缓存 | **融合提案** |
| [prefix/KV caching（agent 架构）](https://huggingface.co/datasets/John6666/forum2/blob/main/mcp_agent_arch_1.md) | 跨轮次复用共享提示段降低 prefill 延迟 | 与"表框架"结合：表框架本身是稳定前缀，天然可缓存 | 仅借鉴 |
| [warm prompts（vllm-mlx）](https://github.com/waybarrios/vllm-mlx/blob/main/docs/guides/warm-prompts.md) | 预热提示 | 预热技巧 | 仅借鉴 |
| [open-webui KV 前缀缓存](https://github.com/open-webui/open-webui/pull/20243) | 运行时注入 RAG 上下文 + KV 缓存优化 | 缓存配置参考 | 仅借鉴 |

**关键结论（白帽提醒）**：
- 省 token 的**最高杠杆**不是"压缩"，而是**稳定前缀 + 缓存命中**：把不变的东西（军团宪法、工具目录卡、表框架）放在最前且保持不变，让它们命中缓存，重复轮次几乎零成本。
- 这和我们之前的"表框架+当前项"设计**天然契合**：表框架是稳定前缀（可缓存），当前项是变化部分（不可缓存），命中率天然高。
- **注意**：prompt caching 是否生效取决于具体模型供应商是否支持，属于"待证"，需实测。

## 四、对规划的增量建议

1. **开发主帅默认思维 = ponytail 精简 + addyosmani 纪律 + superpowers TDD**（三件套蒸馏成常驻规范，不是按需调用的 skill）——直接治"屎山代码"。
2. **"能删就删、能用一行不用两行"写入开发主帅的铁律**（ponytail 的 YAGNI-first + 先查标准库 + 能删就删）。
3. **代码正确度从源头保证**：TDD（先写测试）+ 需求拷打（写代码前先确认需求）+ 系统化调试（不盲试）——不是写完再找 bug。
4. **省 token 靠"稳定前缀 + 缓存命中"**：表框架/宪法/工具目录卡放最前且不变，命中缓存；这是"表框架+当前项"设计的额外红利。
5. **"能力蒸馏"方法论**：进化主帅能把"资深者/大神怎么做"蒸馏进对应主帅（如把 addyosmani 的纪律蒸馏进开发主帅），而不是逐个引入具名 skill。

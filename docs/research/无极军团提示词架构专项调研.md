## 一、核心事实：Claude Code 删 80% 提示词（上下文工程新范式）

**来源**：[Anthropic 官方博客《The new rules of context engineering for Claude 5 generation models》](https://claude.com/blog/the-new-rules-of-context-engineering-for-claude-5-generation-models)（2026-07-24）

**核心内容**：
- Anthropic 为 Claude 5 代模型**删掉了 Claude Code 系统提示词的 80%+**。
- 原因不是"提示词不重要了"，而是：**新模型更强，不再需要那么多"教它怎么做"的规则；反而过多的规则会干扰模型、占 token**。
- 新范式叫 **Context Engineering（上下文工程）**：不再堆规则，而是**设计"该给模型看什么上下文"**——把精力从"写提示词"转移到"组织输入的结构和内容"。

**对无极军团的直接启示**：
1. 我们的"表格图谱"正是上下文工程的核心——**表格就是"组织输入的结构"**。
2. 每个表格/环节的提示词架构，应该**极简、结构化、只保留必要的**，而不是把一堆规则塞进去。
3. 新范式强调"**设计上下文 > 堆提示词**"——这和我们"表框架+当前项"的稀疏投影思想完全同源。

## 三、无极军团的提示词架构设计（核心）

**核心原则：每个表格/环节的提示词 = 结构化、极简、只保留必要的字段。** 不是"写得越多越好"，而是"结构清晰、字段精准"。

### 3.1 阿极的需求表（收集用户需求的标准结构）

```
需求表字段（固定框架，每次只带当前项）：
├── 需求ID / 版本          （定位用）
├── 目标（用户想要什么）      （一句话，不是长篇）
├── 不要什么（边界）          （一句话）
├── 约束 / 优先级           （极简，只留关键）
├── 验收标准（做到什么算好）   （可验证的一句话）
└── 状态（草稿/待确认/已确认）
```

- 每个字段都用**极简的固定格式**，不写解释性废话（模型 5 代已经不需要"教它"）。
- 阿极和用户对话时，就用这个结构去"套"用户的话，套出来的结果天然标准，转给参谋部时就是干净的结构化输入。

### 3.2 参谋部的任务分配表（标准任务契约）

```
任务分配表字段（甘特图式）：
├── 任务ID / 依赖
├── 分给谁（子agent/岗位）
├── 具体要求（极简，可执行）
├── 输入 / 输出格式 / 返回格式（结构化，代码化）
├── 失败处理（重试/换角度/上报）
└── 状态 / 证据句柄
```

- 输入/输出格式用**代码化结构**（CodeAgents 思路），不是自然语言描述——省 token 且无歧义。

### 3.3 各环节通用提示词架构原则

1. **结构 > 文字**：能用字段/表格表达的，不用长段自然语言。
2. **极简字段**：每个字段只留关键信息，删除"教模型怎么做"的规则性废话（新模型不需要）。
3. **稳定前缀 + 变化当前项**：框架字段固定（可缓存），当前值变化（不可缓存）。
4. **代码化参数**：执行代码的参数用结构化格式（JSON/字段），不用自然语言描述。
5. **优先级标注**：明确哪些字段必须看、哪些可忽略（上下文七原则）。

## 四、白帽的提醒（重要，防走偏）

1. **"删提示词"有前提**：Claude Code 删 80% 是因为 **Claude 5 代模型变强了**，能自己推断。我们的 deepseek-v4-flash 是否也"强到不需要详细提示词"，**必须实测**——不能盲目跟风删，否则模型没能力推断，删了反而效果变差。
2. **正确姿势是"结构性精简"，不是"盲目删"**：把"教它怎么做的规则"删掉（模型能自己推断的部分），但**保留"结构、字段、边界"**（模型无法自己知道的部分）。表格字段就是后者——该保留。
3. **压缩方案（ZPL-80）要验证**：压缩提示词可能省 token 但损效果，必须实测"压缩后效果不降"才用。
4. **分档适配**：低档模型（阿极）可能需要稍详细的提示词（因为它弱），高档模型（参谋部）可以极简。**提示词详略也要随模型档位走**，不是一刀切。

## 五、结论

1. **用户的直觉对了**：表格/提示词需要专业架构，这正是 2026 年"上下文工程"新范式的核心——**从"堆提示词"转向"设计上下文结构"**。
2. **表格 = 结构化提示词**：阿极需求表、参谋部任务表、各环节表，都应该是"极简、结构化、字段精准"的提示词架构，转交时天然标准。
3. **关键原则**：结构 > 文字；字段极简；稳定前缀+变化当前项（可缓存）；代码化参数；随模型档位调整详略。
4. **白帽红线**：删提示词的前提是"模型够强能自己推断"，必须实测；正确姿势是"结构性精简"（删规则、留结构字段），不是盲目删。

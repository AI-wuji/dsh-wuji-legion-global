## 〇、三大痛点的调研结论（先说结论）

| 痛点 | 根因（调研证实） | 解法来源 |
|---|---|---|
| **①任务慢** | 后置验证循环（evaluator-optimizer 滥用）、串行依赖、上下文重放、工具 schema 膨胀、无界重试 | 前置限制范式、two-speed 快慢路由、并行扇出、progressive disclosure、熔断（§五） |

## 一、Hermes（爱马仕）自进化原理 —— 用户重点关切，已查清

**结论：Hermes = NousResearch 开源的 hermes-agent 框架（"The agent that grows with you"），与 Hermes LLM 模型无关。其"自进化"不训练模型，是纯 Prompt + 文件机制。**

### 核心机制（源码核实）
1. **三层记忆**（[官方博客](https://hermes-agent.ai/blog/hermes-agent-memory-system)）：
   - **core memory**：长期稳定（用户身份/偏好），可编辑持久化
   - **working memory**：当前会话工作区
   - **episodic memory**：历史情景记忆，跨会话存储与检索
   - 关键：会话结束把对话**压缩蒸馏成记忆条目**写入持久层，不是全量保存；读取按相关性检索注入，不是全量加载

2. **技能引擎**（[官方文档](https://github.com/nousresearch/hermes-agent)）：任务中发现问题 → 自动生成 **SKILL.md**（含触发条件/步骤/边界）固化 → 后续任务语义检索命中自动加载 → 形成"行动→回顾→提炼→固化→复用"学习闭环

3. **学习闭环**（[Learning Loop](https://hermes-agent.ai/features/learning-loop)）：每次任务后回顾表现（哪些方法有效、哪些报错），将可复用方法论/教训蒸馏为技能或记忆条目，下次自动复用——**用得更久变得更强**

4. **DSH 已有三款移植**：官方讨论 [#525](https://github.com/deepseek-ai/deepseek-harness/discussions/525)（MEMORY.md/USER.md 有界记忆 + 技能生命周期策展）、[dsh-hermes-memory](https://github.com/mbj733/dsh-hermes-memory)、[dsh-memory-evolve](https://github.com/csyangwen/dsh-memory-evolve)（五轨记忆 + 技能自进化 + COI 调度）——证明机制可完全用 DSH 原生机制实现

### 融合裁决（融合提案）
- 学习闭环映射进无极军团：任务完成 → 独立官员（只建议）评审 → **参谋部拍板**将可复用套路提纯为 SKILL.md → 入军团技能库 → 下次命中自动装配
- 三层记忆映射：core→阿极用户档案；episodic→sessionProjections 历史任务库；working→当前会话
- **有界记忆**（只写回被证明有用的内容）是治上下文膨胀的根本方案

## 五、解决"慢"的架构模式（痛点①详解）

| 模式 | 来源 | 融合点 |
|---|---|---|
| **orchestrator-workers + parallelization** | [Anthropic 官方](https://claude.com/blog/common-workflow-patterns-for-ai-agents-and-when-to-use-them) | 参谋部=orchestrator 只做 DAG 规划扇出，不逐轮验证；可预测任务走固定 workflow 非 agent 循环；**evaluator-optimizer（生成-评估-重生成）仅留给白帽/质检对高危交付物** |
| **deferred nodes（并行分支）** | [LangGraph](https://changelog.langchain.com/announcements/deferred-nodes-in-langgraph) | 无依赖节点立即并行、有依赖挂起；与 DSH workflow parallel()/pipeline 对应 |
| **progressive tool disclosure（工具渐进披露）** | [LangChain deepagents](https://support.langchain.com/articles/8488719552-progressive-tool-disclosure-with-deep-agents) | 阿极只暴露技能目录卡（名称+一句话+触发），命中后主帅才展开全量指令 |
| **meta-tool 懒加载（~95% 上下文削减）** | [lazy-mcp](https://github.com/voicetreelab/lazy-mcp) | 军团几十个 skill/插件注册表做成 meta-tool+懒加载，未选中零 token 占用 |
| **prompt caching（缓存前缀）** | [Claude Code 经验](https://claude.com/blog/lessons-from-building-claude-code-prompt-caching-is-everything) | 军团宪法/常驻工具/skill 目录卡做稳定前缀；是否命中取决于供应商（待实测） |
| **KV Cache TTL** | [Continuum（ICLR'26）](https://arxiv.org/abs/2511.02230) | 思想落到 sessionProjections：增量摘要+会话内缓存 |
| **熔断（circuit breaker）** | [Infinite Agentic Loops](https://arxiv.org/html/2607.01641v1) | DSH goal max_rounds + jobs 预算硬上限；工具调用指纹，重复 N 次熔断 |
| **回合控制（turn-control）** | [More with Less（arXiv 2510.16786）](https://ar5iv.labs.arxiv.org/html/2510.16786) | 普通任务"一次生成+前置校验"，仅高危用 evaluator-optimizer |
| **two-speed 快慢路由** | [two-speed agent](https://huggingface.co/datasets/John6666/forum2/blob/main/mcp_agent_arch_1.md) | 阿极=快路由（轻量语义分类直答/直调工具，2-3s），参谋部=慢路径（难度分级才规划） |
| **生成前限制范式（guardrails/受约束解码）** | [OpenAI Agents SDK Guardrails](https://openai.github.io/openai-agents-js/zh/guides/guardrails/) | **白帽/质检从"事后挑错"翻转为"事前定义约束"**（工具 schema/输入护栏/输出格式）；非法调用在出生前拦截，验证循环不启动——完全对齐"前置限制>后置验证" |

## 六、解决"融合后比不融合差"的方案（痛点②详解）

**核心学术发现：Skill Shadowing（技能遮蔽效应）**——[《More Skills, Worse Agents?》](https://www.alphaxiv.org/abs/2605.24050) 证明技能库扩大会系统性降低 agent 表现：新增技能遮蔽旧技能，模型在更多候选中出现选择瓶颈。**这为"不叠加"原则提供了学术锚点：融合=压缩选择空间（更少入口、同样覆盖），不是扩充候选。**

| 方案 | 来源 | 融合点 |
|---|---|---|
| **技能 A/B 对照工具** | [skillcheck](https://github.com/sx4im/skillcheck)（with/without 盲评 + bootstrap 置信区间）、[skill-ab-eval](https://github.com/cskwork/skill-ab-eval)（行为差分） | **落地"融合产物 vs 父代同 fixture 对照"**：对每个父代建 fixture 集，跑融合产物/父A/父B/基线四臂 A/B；任一父代维度显著降级即打回重熔 |
| **带评估门的技能演化** | [FederatedSkill](https://www.alphaxiv.org/overview/2606.03143)（遗传+变异+评估器打分）、[AgentSkillOS](https://ar5iv.labs.arxiv.org/html/2603.02176)（组织+基准） | **与"重生"哲学最接近的现成机制**：融合=杂交+变异+选择压（fixture 对照不降级才保留）；互补矩阵按命名/元数据/层级组织 |
| **官方技能质量闭环** | [Anthropic improving skill-creator](https://claude.com/blog/improving-skill-creator-test-measure-and-refine-agent-skills) | 融合产物三查：触发命中/行为生效/价值增益；description tuning 作为微调步骤 |
| **薄入口+分层引用** | [Progressive Disclosure](https://github.com/agentpatterns-ai/website/blob/main/agent-design/progressive-disclosure-agents.md) | 融合产物强制"薄入口 SKILL.md + references/ 分层引用"，入口 token 上限写进融合门评分项 |
| **组合能力评估** | [SKILL-MIX（ICLR'24）](https://huggingface.co/papers/2310.17567) | 对照矩阵加"组合维度"fixture：融合产物+任意其他军团 skill 的组合成功率 |
| **真实使用率统计** | [UCSB Skill-Usage](https://github.com/UCSB-NLP-Chang/Skill-Usage) | 先用运行日志统计各父代真实触发率与成功率；**优先融合高频低效，低频无效直接淘汰** |
| **可复现评测** | [PawBench（AgentScope）](https://github.com/agentscope-ai/PawBench) | 同 fixture 对照必须固定 harness（单模型+固定 Cordis 参数）+ 固定评分器，消除噪声 |

## 七、融合裁决汇总与优先级

### 优先融合（融合提案，P1-P2 落地）
1. **Hermes 学习闭环 + 三层记忆**（§一）——自动进化的主干
2. **AutoSkill 四元组 + 三阶段流水线**（§二）——技能包标准

## 一、系统定位与设计哲学

### 1.1 一句话定位
> 在 DeepSeek Harness 上重建"参谋部中枢制"的无极军团：系统级自动路由让小白用户无感调用 skill/插件/MCP；能力进化机制把同类能力**查漏补缺、取长补短地重生**成更强新物种；独立官员以"只有建议权"的方式做真实验证与反驳。

### 1.2 两条初心支柱
1. **系统级自动调用**：用户只说业务语言，系统自动完成"该用什么能力"的全部选择（skill/plugin/MCP candidates → 只选一条主链路），用户全程无感。
2. **能力进化重生**：同类型能力融合时，不是叠加（父代并列）、不是替换（只留最强），而是**重生**——新物种不属于任何前身，有自己完整的决策结构；父代只是基因来源（谱系）。

### 1.3 六条设计铁律（全部来自实战教训）
| # | 铁律 | 来源 |
|---|---|---|
| L1 | **融合=重生**，必须带互补矩阵 + 同 fixture 对照，不降级才保留 | 教训一 |
| L2 | **并行=真并行**，预检与独立分支并行，禁止"预检串行" | 教训二 |
| L3 | **上下文削减必须覆盖主线程**，投影进每次模型调用 | 教训三 |
| L4 | **前置限制优先于后置验证**，新增验证前必须论证 | 教训四 |
| L5 | **白帽反驳是默认前置机制**，迎合判定不合格 | 教训五 |
| L6 | **独立官员只有建议权、零修改权**，用户采纳 + 阿极转写两步缺一即越权 | 用户强制 |

## 三、组织架构与权限体系

### 3.1 三级建制（用户确认，名字一律保留）
```
军团级：阿极（用户接口）· 参谋部（中枢调度）· 独立官员（审查，只建议）
师团级：各级主帅（能力域负责人，接受参谋部分派）
普通军人岗位：挂在主帅下（通讯员/侦察兵等，单一职能执行岗，不单列平级）
```

### 3.2 权限矩阵（强制，借鉴三省六部"不可越级通信"）
| 主体 | 可写 | 可执行 | 可派发 | 可裁决完成 |
|---|---|---|---|---|
| 阿极 | 需求图（唯一） | 否（只交流） | 否 | 否 |
| 参谋部 | 执行图/验收图（唯一） | 否（调度不执行） | 是（向主帅/工兵） | 否（只对账证据） |
| 各级主帅 | 各自能力域产物 | 是（师团内） | 是（向普通军人岗位） | 否 |
| 独立官员 | **无（零修改权）** | 否 | 否 | 否（只建议） |
| 普通军人岗位 | 被派发范围的产物 | 是 | 否 | 否 |

**权力边界三层**：官员只能建议 → 用户决定 → 阿极执行。官员建议须经"用户采纳 + 阿极转写"两步进入正式状态。

## 四、核心子系统详细设计

### 4.1 参谋部（军团调度中枢）—— 解决"慢"

**职责**：task-routing → capability-mount → deterministic-execution，单一主链。

**路由策略（two-speed）**：
```
用户请求
  → 阿极快路由（轻量语义分类，2-3s 直答或直调工具）
      │ 简单任务：直接在主线程执行（直道优先），不过完整链路
      ▼ 非平凡任务
  → 参谋部慢路径（确定性触发词优先 → 语义召回兜底 → 才问用户）
      → capability-mount：skill_candidates / plugin_candidates / mcp_candidates 各至多选一
      → 分派（并行扇出独立分支，DAG 依赖顺序执行）
```

**并行规则（L2）**：预检与独立分支**必须并行**（DSH `subagent`/`workflow`/`parallel()`）；搜索类默认按"官方/GitHub/社区"分方向并行；并行度由 jobs 预算约束。

**熔断（防死循环）**：goal `max_goal_rounds` + jobs 预算硬上限；工具调用指纹（同工具连续失败或相同调用重复 N 次即熔断），转交人类；熔断事件由审计官登记。

### 4.2 军团技能库（能力注册）—— 解决"选择难"

**技能格式（对齐 Anthropic/OpenAI 双生态标准）**：
```
技能目录/
├── SKILL.md            # 薄入口：YAML frontmatter(name/description/触发条件/边界) + 概览
└── references/         # 详细步骤/脚本/资产，按需读取（渐进披露）
```
- 系统提示中**只注入技能元数据目录**（name/description），模型靠 description 匹配后自行展开正文（Progressive Disclosure）。
- 未选中技能**零 token 占用**（meta-tool 懒加载思想，实测可削减 ~95% 上下文）。

**技能生命周期**（矩阵 E1）：
```
known → callable → behavior-verified → primary
（发现 → 入口可跑 → 真实产物+SHA-256 证据 → 对照不降级晋升）
```

**注册表 schema（wuji-registry）**：
```json
{
  "id": "技能稳定ID",
  "level": "军团|师团|军人岗位",
  "owner": "归属主帅/岗位",
  "triggers": ["触发词..."],
  "entrypoint": "SKILL.md|插件|脚本",
  "lifecycle": "known|callable|behavior-verified|primary",
  "verify": "探针脚本路径",
  "fallback": "默认回退路径",
  "sources": ["谱系来源ID..."],
  "context_budget": "字节预算"
}
```

### 4.3 能力进化系统（进化主帅）—— 解决"自动进化"

**总体流程（Hermes 学习闭环 + 无极审核）**：
```
任务执行（打赢的战役）
  → 独立官员（只建议）评审：哪些方法有效/哪些报错
  → 参谋部拍板：可复用套路提纯为 SKILL.md 草案
  → 技能管理器：草案入册候选区
  → 进化主帅裁决（互补矩阵 + 四臂 A/B 对照）
  → 不降级才入库（版本化，可回滚）
  → 下次任务命中自动装配
```

**技能定义（AutoSkill 四元组）**：
```
技能 = { trigger(触发条件), description(描述), process(执行过程), reflection(反思) }
```

**进化三阶段流水线（AutoSkill）**：
1. **归纳**（Induction）：从任务经验提炼新技能
2. **组合**（Combination）：合并/重组相关技能（对应"融合=重生"）
3. **泛化**（Generalization）：迁移到新场景

**"重生"算法（Trace2Skill 分层合并 + 互补矩阵）**：
```
父代A + 父代B（同类）
  → 并行归纳：分别提炼各自"局部教训"
  → 分层合并：去重、取长补短（互补矩阵：A优点/A缺点/B优点/B缺点/新决策结构）
  → 生成新物种（不是 A 也不是 B，有自己完整决策结构）
  → 四臂 A/B 对照（融合产物 / 父A / 父B / 无skill基线）
  → 任一父代维度显著降级 → 打回重熔；全部不降级 → 入库
```

**验证信号自进化（OpenSkill）**：把质检官员的验证标准做成**可进化的"验证技能"**——新技能入册时自动复用既往验证信号，逐步摆脱每次人工/LLM 复盘验证（治"慢"）。

**单模型自我蒸馏（SEED）**：deepseek-v4-flash 单模型环境下，用"自我同策略蒸馏"把成功/失败会话的**教训**（而非答案）提炼为 skill/prompt 片段注入后续会话——不增加推理成本。

**版本化回滚（dsh-continual-evolve）**：每次进化先过基准验证再落盘，失败可回滚旧版；进化提案必须附基准通过证据。

**记忆策略进化（MemSkill / Meta Context Engineering）**：让阿极的上下文管理策略（何时记/记什么/如何压缩）成为**可进化技能**，替代写死的裁剪规则。

**动态能力生长（dsh-evolve）**：主帅在战斗中即时热挂载/卸载工具插件（不重启、可逆、持久化、重启自动恢复）——能力按需装配，非永久叠加。

### 4.4 军团档案（上下文系统）—— 解决"上下文大"

**三层记忆（Hermes）映射**：
```
core memory     → 阿极用户档案 + 军团宪法（长期稳定，可编辑持久化）
episodic memory → sessionProjections 持久化历史任务库（参谋部整理）
working memory  → 当前会话工作区
```
- 会话结束把对话**压缩蒸馏成记忆条目**写入持久层（非全量保存）。
- 读取按相关性**检索注入**（非全量加载）。
- **有界记忆**：只写回被证明有用的内容（白名单制），天然控制上下文增长。

**稀疏投影（矩阵 C1-C16，核心）**：
| 角色 | 自己的表 | 每次调用投影 | 写入者 |
|---|---|---|---|
| 阿极 | 需求图/决策图/证据索引 | 当前活跃单元+依赖+版本指针+当前消息 | 阿极 |
| 参谋部 | 执行图/验收图/尝试账本 | 当前节点+依赖+契约+回执 | 参谋部 |
| 进化主帅 | 谱系融合图/经验图 | 命中事件对应经验节点 | 进化主帅 |
| 独立官员 | 隔离观点图 | 同一事实快照+职权模板 | 官员（只建议） |

**实现（关键）**：`sessionProjections` 原生服务承载——投影注入 `systemPrompt.variable()` + `agent/pre-step`（**每次模型调用生效**），完整历史留冷存储。

**上下文审计**：`wuji-context-doctor`（借鉴 dsh-context-doctor）定期统计 AGENTS.md/技能目录/工具 schema 的 token 成本，检测重复与冲突 → 精简 → 压缩闭环。

**工具渐进披露**：阿极只暴露工具目录卡（名称+一句话+触发），命中后主帅展开全量 schema。

### 4.5 独立官员（军团监察）—— 解决"融合更差"与"迎合"

**执行形态（O4，用户确认）**：
- **MoE 单子 agent 承载全部职权**（默认）：每次只激活一个职权，共享上下文骨架，启动成本≈0。
- **隔离多子 agent 盲审**（罕见）：仅用户明确要求"多堂会审/群策群力"时启用（3.0 首轮互不可见协议）。
- 官员审**任务/产物**，不是彼此 → MoE 档无串台问题。
- 触发 = 契约自动、无人工干预（失败→根因官；高风险→保卫科；发布→审计/合规）。

**白帽（L5，防迎合核心）**：
- 命名源流：宪兵（白钢盔），执法纠错不徇私，**反驳而非迎合**。
- **默认不独立启动**：反驳义务是人格层机制（preset persona 强制"方案确认前必须输出假设/反例/风险/备选，不允许迎合"），0 额外成本。
- **默认开启**：每次方案确认前，阿极必须先输出一次白帽视角；用户知情后再确认。
- 用户确认后白帽退出热路径（不干扰执行）。
- **防纯抬杠**：白帽 = 怀疑派 + **Steelman（反方最强者论证）**双角色——先替用户把想法最合理的版本说出来，再攻击它。
- 独立形态（罕见）：用户明确要求时才启动隔离 subagent。

**权限（L6）**：只有建议权、零修改权——不写需求/执行/产物/图谱，不派发/不否决/不裁决完成；输出只能是"建议回执"（建议ID/职权/内容/证据/因果线），用户采纳后由阿极转写。

### 4.6 军团门禁（保卫科）—— 前置限制

- 受控动作（联网/外部下载/引入 skill·MCP/写文件/凭据/发布/删除）**发生前**触发确定性门禁（tools/pre-execute 瀑布 + approval 栈）。
- 模型默认休眠，不轮询、不耗 Token。
- **前置限制优先（L4）**：scope/边界/约束/验收标准/禁止项在生成前写进任务契约（goal boundary lock），后置验证只留高风险不可逆动作的一次性门禁。
- 秘密不保留、不复述、不传播，只留不透明 vault 引用；泄露即轮换。

## 五、关键流程

### 5.1 一条主链路（小白视角）
```
用户："帮我整理飞书里那个表格，做成PPT发群里"
  → 阿极接收（业务语言，不暴露任何技能术语）
  → 白帽视角前置（假设/反例/风险/备选，用户知情）
  → 参谋部路由：lark-sheets → presentation → lark-im
  → capability-mount：自动装载对应能力（技能目录卡→展开全量）
  → 执行：师团主帅组织（子agent/工作流并行）
  → 前置限制内验证 → 阿极汇报
  → 用户全程只看到业务语言与结果
```

### 5.2 融合进化流程（重生门禁）
```
同类能力候选
  → 使用率统计（UCSB 方法）：高频低效优先融合，低频无效直接淘汰
  → 互补矩阵（父代优点/缺点/新决策结构）
  → 同 fixture 四臂 A/B（skillcheck：融合/父A/父B/基线，bootstrap 置信区间）
  → 任一父代维度显著降级 → 打回重熔
  → 全部不降级 → 版本化入库（可回滚）
  → 薄入口 SKILL.md + references 分层（渐进披露）
```

### 5.3 官员审查流程
```
契约触发（失败→根因；高风险→门禁；发布→审计/合规）
  → MoE 单 agent 内激活职权（默认）或隔离 subagent（会审档）
  → 输出"建议回执"（建议ID/职权/内容/证据/因果线）
  → 用户采纳/拒绝/暂缓（O7）
  → 采纳后由阿极转写为正式状态
  → 官员无任何修改权，两步缺一即越权
```

## 六、技术规范

### 6.1 技能包格式（强制）
```
技能名/
├── SKILL.md               # 必须：frontmatter(name/description/triggers/boundaries) + 概览 + 关键步骤
├── references/            # 可选：详细文档/模板/资产（按需读取）
├── scripts/               # 可选：执行脚本（探针/工具）
└── verify.*               # 探针：真实产物 + SHA-256 证据（E3）
```

### 6.2 互补矩阵模板（融合立项必须附带）
| 维度 | 父代A | 父代B | 新物种 |
|---|---|---|---|
| 优点 | ... | ... | 继承哪些 |
| 缺点 | ... | ... | 弥补哪些 |
| 重复 | ... | ... | 删除哪些 |
| 新决策结构 | - | - | 父代没有的 |

### 6.3 投影单元 schema（sessionProjections 注册）
```
{ key, schema(zod), init(), apply(state, event), view(state), stateVersion }
三个域：需求单元 / 执行节点 / 官员建议
```

### 6.4 指挥官链权限（subagents 所有权约束）
- 阿极 → 参谋部（唯一）
- 参谋部 → 各级主帅（分派）
- 主帅 → 普通军人岗位（师团内）
- 官员 → 无派发权（不调用任何主体）

## 九、验收标准（三大痛点是否真解决）

| 痛点 | 验收指标 |
|---|---|
| **慢** | 简单任务直道 2-3s；无依赖分支并行；无死循环（熔断触发可证）；后置验证仅剩高危一次性门禁 |
| **融合更差** | 每次融合过四臂 A/B，任一父代维度不降级；技能库只挂元数据（渐进披露），选择瓶颈不恶化（Skill Shadowing 度量） |
| **上下文大** | 每次模型调用只投影当前单元（sessionProjections 生效可证）；未选中技能零 token；上下文审计报告 token 持续受控 |

## 十、结论

新无极军团 = **系统级自动路由（小白无感）** × **能力进化重生（越用越强）** × **白帽反驳（防迎合）** × **前置限制（快且稳）**，全部构建在 DSH 原生机制之上（sessionProjections / subagent / workflow / cordis 动态插件），外部项目只作方法借鉴、不进命名，组织完全采用无极三级建制。

本框架为终版实施蓝图；后续实施以本文为准，细节冲突以《设计资产清点与DSH适配矩阵》v1.8 为准。

# 无极军团 · 新体系总纲

> 版本：v1.0（总纲，2026-08-15）
> 平台：DeepSeek Harness（DSH）
> 依据：本总纲是**入口文档**；权威细节以《无极军团设计资产清点与DSH适配矩阵》（v1.8）为准，本总纲只引用其行号。
> 性质：完整介绍文档——说清新无极军团是什么、为什么、怎么运行、怎么落地。

## 一、初心（我们为什么做这件事）

> 让**不了解** Skill / 插件 / MCP 是什么的小白用户，遇到问题时由**系统级**的无极军团自动识别并调用对应能力执行任务，全程无感；同时把同类能力**蒸馏、融合、进化**成更强的新插件，以更快速度、更高质量服务用户。

两条初心支柱：
1. **系统级自动调用**：用户只说要什么（业务语言），系统自动完成"该用什么能力"的选择，用户不需要知道 skill/插件/MCP 这些概念。
2. **能力持续进化**：同类型的插件通过查漏补缺、取长补短，重生成更强的新物种；不是叠加，不是替换，是**重生**。

## 二、组织架构（三级建制）

> 命名体系：全部使用无极军团自己的建制命名（用户原创体系），不引入外部组织名/项目名/人名。现有名字（阿极/参谋部/主帅/独立官员）一律保留。

```
军团级（顶层，名字保留不更名）
├── 阿极            —— 军团级用户接口（唯一对话入口）
├── 参谋部          —— 军团级中枢（调度/拆解/capability-mount，管辖全部师团）
└── 独立官员        —— 军团级审查（白帽/质检/审计/合规/根因/性能/综合）

师团级（接受军团级参谋部分派）
└── 各级主帅        —— 师团级负责人（进化主帅/内容主帅/视觉主帅/开发主帅/情报主帅/安全主帅…）

普通军人岗位（挂在某个主帅之下，单一职能执行岗）
└── 如：通讯员      —— 某师团下的信息传递/状态上报岗
      侦察兵/采集员/传令兵 等可按需增设
```

| 角色 | 层级 | 职责 | 权限 |
|---|---|---|---|
| 阿极 | 军团级 | 用户交流、需求澄清、汇报；不执行、不验收 | 需求图唯一正式写入者 |
| 参谋部 | 军团级 | 理解指令→分类→拆任务→capability-mount→调度 | 执行图唯一正式写入者；唯一预加载中枢 |
| 各级主帅 | 师团级 | 能力域负责人（进化主帅管融合、保卫科管门禁、各能力主帅管领域） | 各自领域运行职责 |
| 独立官员 | 军团级 | 审查（白帽反驳/质检/审计/合规/根因/性能） | **只有建议权，零修改权** |
| 普通军人岗位 | 师团级下 | 单一职能执行（通讯员/侦察兵等） | 只做被派发的单项职能 |

**核心权力边界（三层）**：
```
官员只能建议 → 用户决定 → 阿极执行
```
- 独立官员只有建议权，没有任何修改权（不写需求/执行/产物/图谱；不派发/不否决/不裁决完成）。
- 官员建议须经"用户采纳 + 阿极转写"两步才进入正式状态，缺一即越权（O4/O7）。

## 三、核心机制

### 3.1 系统级自动路由（初心①）

```
用户："帮我整理飞书里那个表格，做成PPT发群里"
  → 阿极接收（业务语言，不暴露任何技能术语）
  → 参谋部路由：lark-sheets(表格) → presentation(PPT) → lark-im(发群)
       （skill_candidates / plugin_candidates / mcp_candidates 各至多选一）
  → capability-mount：自动装载对应能力
  → 执行（子agent/工作流）→ 前置限制内验证 → 阿极汇报
  → 用户全程只看到业务语言与结果
```

路由策略（O1）：
- **确定性优先**：触发词（沿用 17 个能力包 manifest）命中即路由，零模型往返。
- **语义兜底**：未命中走语义召回（借鉴 semantic-router 思路）。
- **再未命中才问用户**：用业务语言问，不是技能术语。
- **直道优先**：简单任务直接在主线程执行，不经过完整链路（two-speed 思路）——治理复杂度随任务难度增长，不固定压在每次任务上。

### 3.2 能力融合进化（初心②）

**融合 = 重生（E2）**：
```
不是叠加（父代规则并列 = 错）
不是替换（只留最强 = 错，丢互补）
是重生：查漏补缺、取长补短的新物种，不属于任何一个前身
```

**融合强制流程**：
1. 能力审计（盘点同类，输出互补矩阵：父代A优点/缺点、父代B优点/缺点、新决策结构如何取长补短、删除了哪些重复）
2. 同 fixture 前后对照（融合产物 vs 父代，hash/断言不降级才保留）
3. 过行为验证门禁（callable → behavior-verified，真实产物 + SHA-256）
4. 才进入默认热路径

**能力生命周期**：known → callable → behavior-verified → primary（E1/E3）

### 3.3 上下文图谱（稀疏投影）

**每角色一表、每次只投影有限内容（C1-C16）**：

| 角色 | 自己的表（图谱） | 每次调用投影的内容 | 写入者 |
|---|---|---|---|
| 阿极 | 需求图/决策图/对话证据索引 | 当前活跃单元 + 必要依赖 + 版本指针 + 当前消息 | 阿极 |
| 参谋部 | 执行图/验收证据图/尝试账本 | 当前执行节点 + 依赖 + 契约 + 回执 | 参谋部 |
| 进化主帅 | 谱系融合图/全局经验图 | 命中事件对应的经验节点 | 进化主帅 |
| 独立官员 | 隔离观点图（按次） | 同一事实快照 + 自己的职权模板 | 官员（只建议） |

**实现（关键）**：DSH 原生 `sessionProjections` 服务直接承载（goal/todo/token 都在用）——投影注入 `systemPrompt.variable()` + `agent/pre-step`（每次模型调用生效），完整历史留冷存储，不重放。

### 3.4 独立官员体系（MoE 化执行）

**执行形态（O4）**：
- **MoE 单子agent 承载全部职权**（默认）：每次只激活一个职权，共享上下文骨架，启动成本≈0。
- **隔离多子agent 盲审**（罕见）：仅用户明确要求"多堂会审/群策群力"时启用（3.0 首轮互不可见协议）。
- 官员审的是**任务/产物**，不是彼此 → MoE 档不存在串台问题。
- 触发 = 契约自动、无人工干预（失败→根因官；高风险→保卫科；发布→审计/合规）。

**白帽（防迎合核心，教训五）**：
- 白帽 = 宪兵（白钢盔），职责是**反驳而非迎合**：从用户利益出发找反例、风险、错误假设、遗漏。
- **默认开启**：方案确认前，阿极必须先输出白帽视角（假设/反例/风险/备选）；"迎合用户、不提反例"判定不合格。
- 默认不独立启动（人格层义务，0 成本）；用户明确要求时才启动隔离实例。

### 3.5 保卫科门禁（前置限制）

- 受控动作（联网/外部下载/引入 skill·MCP/写文件/凭据/发布/删除）**发生前**触发确定性门禁（O6）。
- 模型默认休眠，不轮询、不耗 Token。
- 秘密不保留、不复述、不传播，只留不透明 vault 引用；泄露即轮换（G6）。

## 四、实战教训（防止重蹈覆辙）

> 全部来自真实使用复盘，已固化为强制规则。

| 教训 | 问题 | 规则 |
|---|---|---|
| **教训一** | 融合 = 并列堆叠（presentation 9 上游并列），不如单 skill | 融合必须带**互补矩阵** + 同 fixture 对照；出现"Internally use A…B…"并列式指令即判不合格 |
| **教训二** | 并行被"预检强制串行"压制 | 预检与独立分支**必须并行**（DSH subagent/workflow/parallel 原生支持）；搜索按官方/GitHub/社区分方向并行 |
| **教训三** | 子 agent 独立了上下文，但主线程没省 | 投影必须进**每次模型调用**（systemPrompt.variable + agent/pre-step）；工具/skill 目录按需呈现 |
| **教训四** | 后置验证是慢的根源（生成→验证→重做→再验证） | **前置限制优先**：scope/边界/约束/验收/禁止项在生成前锁定；后置验证只留高风险不可逆动作的一次性门禁；新增验证前必须论证"为何不能前置限制替代" |
| **教训五** | 白帽缺失 → 模型一味迎合用户 | 白帽=默认前置机制；方案确认前强制反方视角；迎合判定不合格 |

## 八、关键结论

1. **初心两支柱 = 系统级自动路由 + 能力进化重生**，前者让小白无感，后者让能力持续变强。
2. **组织 = 三级建制**（军团级阿极/参谋部/独立官员 → 师团级主帅 → 普通军人岗位），命名独立体系。
3. **权力边界三层**：官员只能建议 → 用户决定 → 阿极执行；官员零修改权。
4. **速度靠前置限制 + 直道优先 + 真并行**，不是靠后置验证堆砌。
5. **质量靠白帽反驳（防迎合）+ 行为验证门禁（防堆叠）**。
6. **上下文靠稀疏投影进调用路径**，不是生成一个文件了事。
7. **全部裁决落在《设计资产清点与DSH适配矩阵》v1.8**，迭代从矩阵出发，不依赖回忆。

## 一、模型分级路由（对应"只定档不定型号"）

| 项目 | 机制 | 融合点 | 裁决 |
|---|---|---|---|
| [RouteLLM（ICLR'25）](https://arxiv-org.ezproxy.obspm.fr/abs/2406.18665) | 从偏好数据学习"何时用强模型、何时用弱模型"的路由器；成本下降同时质量不降 | **档位映射的现成算法**：可训练/可规则的路由器，把"哪个模型属于哪档"从静态配置升级为动态判断 | **融合提案** |
| [Microsoft BEST-Route](https://github.com/microsoft/best-route-llm) | 按查询难度选模型+响应数，成本降 60%、性能降 <1% | 参模部派发时的**难度分级依据**：先用轻量信号判难度，再选档 | **融合提案** |
| [AgentRouter（ICML'26）](https://icml.cc/virtual/2026/74502) | 异构模型路由，为多步 agent 工作流的**每一步**选最优模型 | 关键升级：不是"一个任务一个模型"，而是**每个子 agent 按各自步骤难度选模型**——正好对应我们"子 agent 按难度分档" | **融合提案** |
| [ACRouter](https://venturebeat.com/orchestration/acrouter-picks-the-smartest-ai-model-per-task-beating-opus-only-setups-by-2-6x-on-cost) | 每任务选最智能模型，比只用最强模型省 2.6x 成本 | 成本-质量权衡的实证参考 | 仅借鉴 |
| [Replay Gap 论文](https://scirate.com/arxiv/2608.08239) | 警示：模型切换的静态评估可能"评错世界"（replay gap） | **白帽提醒**：模型分级不能只靠离线评测，要在真实运行里验证切换效果 | 仅借鉴 |

**关键结论**：模型分级有成熟算法支撑，且 AgentRouter 证实"每一步/每个子 agent 单独选模型"比"整体选一个"更优——这直接强化了我们的"子 agent 按难度分档"设计。

## 二、流水线容错（对应"失败重派+熔断"）

| 项目 | 机制 | 融合点 | 裁决 |
|---|---|---|---|
| [circuit_breaker（agent-runtime-mcp）](https://github.com/marc-shade/agent-runtime-mcp/blob/main/circuit_breaker.py) | agent 运行时熔断器 | 熔断的现成实现参考：连续失败自动短路 | **融合提案** |
| [cascadeflow retry+circuit breaker](https://github.com/lemony-ai/cascadeflow/commit/6e65bf6815a1bcb66f89108298f72ea438057104) | 工具调用经重试+熔断路由 | 工具级重试+熔断的落地方式 | 仅借鉴 |
| [GraphBit 错误处理架构](https://huggingface.co/blog/Musamolla/agent-error-handling-architecture) | 错误检测→分类→缓解策略（detection/classification/mitigation） | **失败重派的结构化**：失败不是笼统"再试"，而是先分类（瞬态/确定性/能力缺失），再定策略（重试/换角度/上报） | **融合提案** |
| [task-orchestrator](https://github.com/TC407-api/task-orchestrator) | 多 agent 任务编排器 | 编排骨架参考 | 仅借鉴 |

**关键结论**：GraphBit 的"错误三分类"是重点——失败重派要先判断失败类型（瞬态故障→直接重试；确定性错误→换角度；能力缺失→上报），而不是笼统重试。这比我们之前的"最多换 3 角度/5 次"更精细。

## 三、表格/上下文压缩（对应"表框架+当前项"）

| 项目 | 机制 | 融合点 | 裁决 |
|---|---|---|---|
| [LLMLingua](https://blog.gitcode.com/2c07ce8ff77edfc89372055d0eeee47e.html) | 提示词压缩（保留关键 token 去冗余） | 表内容的压缩手段，进一步降上下文 | 仅借鉴 |
| [SeCom（微软 ICLR'25）](https://github.com/microsoft/SeCom) | 记忆构造与检索：个性化对话 agent 的记忆分层 | **三层记忆的具体实现**（哪些该存、怎么检索） | **融合提案** |
| [What to Keep, What to Forget（Rate-Distortion 记忆压缩）](https://arxiv-org.ezproxy.obspm.fr/html/2607.08032v1) | 用率失真理论决定"保留什么、遗忘什么" | **有界记忆的理论依据**：只存对任务有用的，量化"存什么不存什么" | **融合提案** |

**关键结论**：SeCom 和 Rate-Distortion 论文证实"有界记忆"（只存有用的、量化保留/遗忘）是行业共识方向，我们的"三层记忆 + 有界写回"有理论支撑。

## 八、对规划的增量建议

1. **失败重派升级为"错误三分类"**（GraphBit）：失败先分类——瞬态故障直接重试、确定性错误换角度、能力缺失上报，而不是笼统"再派一个"。
2. **模型分级支持"每子 agent 单独选档"**（AgentRouter）：不只是阿极/参谋部/子agent 三档，而是每个子 agent 按自己那步的难度独立选档。
3. **技能检索加语义层**（skill-depot + semantic-router）：技能库大了后，元数据快速匹配 + 语义检索兜底。
4. **回滚加检查点**（agent-rollback）：每次技能修改前先建检查点。
5. **有界记忆有理论依据**（SeCom + Rate-Distortion）：量化"存什么、不存什么"。

**白帽提醒**：模型切换要防"replay gap"（静态评估评错世界），必须在真实运行里验证；回滚机制本身要防滥用（ACRFence）。

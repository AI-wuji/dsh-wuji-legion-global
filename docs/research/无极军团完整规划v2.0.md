# 无极军团 · 完整规划（v2.2 · 系统级下沉版 + 系统复查补全）

> 版本：v2.2
> 日期：2026-08-15
> 平台：DeepSeek Harness（DSH，Cordis 插件系统）
> 核心原则：
> 1. **能沉到系统级就不浮在表层**——每个角色都做成真正的 DSH 插件/服务，不是 persona 文字或 skill 文件。
> 2. **一切优先复用 DSH 原生能力**，不重造轮子。
> 3. **角色能力只用"官方/高星 + benchmark"背书的**，不臆断。
> 4. 名字用无极建制，外部项目只学方法不借名字。
>
> v2.2 变更：① 情报官定位修正——**只搜集不分析**（分析归参谋部），情报官用最低档模型（DecoupleSearch 解耦搜索与规划背书）；② 情报官能力补 awesome-agentic-search。

# 一、初衷（一切的根本，完整保留）

> **让不了解插件、Skill、MCP 是什么的小白用户，在遇到问题时，由系统级的无极军团自动调用相对应的能力去执行任务，而不需要用户手动去选择具体要用什么 Skill 或 MCP。**

> **同时，把同类型的能力复制、蒸馏、融合，整合成能力更强的新插件，以更快的速度、更高的质量为用户服务。**

**两条支柱（判断一切的尺子）**：
1. **系统级自动调用（无感）**——用户只说人话，系统自己决定"该用什么能力"，全程不让用户接触 skill/插件/MCP 概念。
2. **能力进化重生（越用越强）**——复制、蒸馏、融合同类能力成更强新物种。融合不是叠加（并列塞一起）、不是替换（只留最强），而是**查漏补缺、取长补短地重生**。

# 二、架构定位（v2.0 核心转变：从"应用"下沉到"系统"）

## 2.1 之前的问题（v1.x 的定位错误）

v1.x 把无极军团做成了"浮在 DSH 上面的应用"——用 persona 文字模拟阿极、用 skill 文件模拟主帅、用抽象概念模拟门禁。**设计很好，但执行层跑偏了，因为这些都是"表层"，没有真正嵌进 DSH 底层。**

# 三、组织架构（三级建制，名字保留）

```
军团级
├── 阿极        —— 会话层用户接口（收集需求/澄清/填表/汇报，低端模型）
├── 参谋部      —— 宿主层调度中枢（拆任务/调度/监控反馈，最高智商）★主 Skill 中枢
└── 独立官员    —— 执行层审查（白帽/质检/审计/合规/根因/性能/综合，只建议）

师团级
└── 各级主帅    —— 执行层能力域负责人（内容/视觉/开发/情报/数据/安全/攻防/进化）

普通军人岗位
└── 通讯员等    —— 主帅域内的单一职能执行岗
```

**安全三职责（方向不同，不能混）**：
| 职责 | 角色 | 方向 | 管什么 |
|---|---|---|---|
| 对外防御 | 安全主帅 | 防外 | 引入的外部 skill/插件/MCP/文件/信息里的木马、病毒、广告、恶意代码 |
| 攻防 | 攻防主帅 | 双向 | 破译闭源原理/元指令（借鉴，合法边界内）+ 加密自己产出物（防破译） |
| 自查 | 质检/审计官 | 对内 | ① 蒸馏融合后"化学反应"涌现的新漏洞/bug；② 自己插件等产出物的漏洞 |

> 安全主帅≠攻防主帅≠自查：三个方向、三个角色、三套能力。之前混淆，现已厘清。

**权力边界三层（强制）**：官员只能建议 → 用户决定 → 阿极执行。
- 独立官员**只有建议权、零修改权**（不写表、不派发、不否决、不裁决完成）。
- 官员建议须经"用户采纳 + 阿极转写"两步才生效，缺一即越权。

**白帽（防迎合核心）**：宪兵（白钢盔），反驳而非迎合。默认开启、默认不独立启动（人格层义务，0 成本）；怀疑派 + Steelman 双角色防纯抬杠。防迎合有**官方依据**（Anthropic Persona Vectors 可编辑 sycophancy、OpenAI 官方承认并回滚谄媚版）。

# 四、核心运行机制（v1.5 保留，落点下沉）

## 4.1 流水线执行（不是讨论会）

阿极收集需求 → 参谋部拆成任务表（甘特图式）→ 配发给多个主帅/子 agent → 并行执行（各拿各的上下文）→ 参谋部实时接收反馈（成功汇总、失败重派）→ 有依赖串行、无依赖并行。

**纪律**：
- 失败重派熔断上限（3 角度/5 次）+ 冷却 cooldown（防雪崩）+ 换角度基于置信度/错误类型。
- 子 agent 三铁律：状态隔离 / 原子通信 / 契约化错误处理。
- 参谋部自适应重规划（执行中根据反馈调整，不拆完死板执行）。
- 拆解依据：**"子 agent 能否独立执行"**（Agent-Oriented Planning，ICLR'25）。

## 4.2 模型分级（只定档不定型号）

| 角色 | 档位 |
|---|---|
| 阿极 | 低档（便宜快速）|
| 参谋部 | 高档（最高智商）|
| 情报官 | 最低档（只搜集不分析，便宜快速）|
| 各级主帅 | 中档 |
| 子 agent | 按任务难度分档（低/中/高）|

**档位 = 能力契约，模型 = 运行时配置**——`llm.registerAdapter` 注册各档 adapter，运行时在"当前可用模型"里动态映射。

**关键分工（搜集与分析彻底分开）**：情报官**只负责搜集**（搜索/抓取/提取），**不分析**——分析是参谋部的事。所以情报官用最低档模型（搜集不需要推理），参谋部用最高档（分析才需要高智商）。这正是 [DecoupleSearch（EMNLP 2025）](https://aclanthology.org/2025.emnlp-main.222/) 的"解耦搜索与规划"——搜索执行用便宜模型、分析规划用强模型。

## 4.3 表格图谱（框架 + 当前项，稀疏投影）

每岗位一张表，每次只带"**表框架（所有标题）+ 当前项全文 + 版本指针 + 当前消息**"。可下潜、可跨单元显式引用（有界）。稳定前缀 + 缓存命中（省 token）。

**下沉落点**：`sessionProjections.register`（三张表：需求表/任务表/官员建议表）+ `systemPrompt.variable()`（每次调用注入框架+当前项）。

## 4.4 能力进化（自动进化闭环）

进化 = 重生（SkillPacks 模块化组合 + Grafting 嫁接）。

闭环：打赢漂亮仗 → 官员点评 → 参谋部拍板提纯技能草稿 → 进化主帅审查（互补矩阵）→ 行为探针验证 → 版本化入库（可回滚）→ 下次命中自动装配。

**下沉落点**：进化主帅监听 `tools/result` 事件，用 `cordis_define` 定义新插件。**注意**：DSH 官方"自进化蓝图"（agent 运行中改写自己）是**机制载体**，无极进化②（能力融合）才是本体——两者不是一回事，但前者为后者提供落地能力。

**融合门禁**：互补矩阵（证重生）+ 行为探针（证真能力）。**能力入库必须带 benchmark**（secpriv 模式：detector-validator + benchmark），不是 README 自吹。不做 A/B 同类较量。

## 4.5 上下文工程（结构化工程，贯穿从内到外）

一条原则：一切文本（内部传的 + 对外产的）都从诞生起**结构化、极简、可复用、源头内建**。

- **内部通信**：表格极简字段，参数代码化，随档位调详略。
- **代码工程**：精简（ponytail）+ 规范（addyosmani）+ 正确度（superpowers TDD）+ docstring 语义锚点。
- **对外产出**：代码/元指令/插件/技能各有规范，带元数据 + 可复用形态。

## 4.6 根因修复（复发驱动的有界治本）

发现 bug → 快修 + 记录指纹 → 第一次到此为止 → 复发才触发根因官深挖（四阶段 + 深度上限）→ 治本 + 沉淀经验。

## 4.7 安全、并发、检查点、可观测、记忆

- **安全凭据**：密钥不进入上下文/日志/图谱，只留 vault 引用；引入前审查；最小权限（`tools.restrict`）。
- **并发隔离**：派发时划界（谁写哪块），共享对象加写锁。
- **任务检查点**：中断后从最近检查点恢复（sessionProjections 持久化）。
- **可观测**：sessionTelemetry 指标 + messageFeedback 反哺进化。
- **记忆**：三层记忆（core/working/episodic）+ 有界写回 + 混合检索（向量/关键词/图）。

# 九、验收标准

| 维度 | 指标 |
|---|---|
| 下沉 | 每个角色都是真实 DSH 插件/服务（不是 persona 文字/skill 文件）|

# 十、总结

**新无极军团 v2.0 = 系统级下沉的插件组合**——参谋部/进化主帅/保卫科/表格图谱沉到宿主层（真服务），阿极/白帽沉到会话层（真 agent + 真事件），各级主帅/官员沉到执行层（真 provider）。每个角色都有官方/高星背书的真实能力，能力入库带 benchmark。站在 DSH 原生能力上（subagents/sessionProjections/tools.guard/cordis 动态插件），把 DSH"改造成无极军团"，而非浮在上面的应用。

**两条初心支柱始终第一优先级**：① 用户永远不用选技能；② 融合永远是重生。

# 十一、系统级补充机制（v2.1 系统复查补全，10 处遗漏，全部数据背书）

> 来源：《系统复查遗漏清单》v2.0。所有补充均对应全网搜索到的真实、已验证能力，无臆想。

## 11.1 角色补充

- **进化主帅 = 宿主层元主帅**（管能力融合治理），**能力主帅 = 执行层域主帅**（内容/视觉/开发/情报/数据/安全/攻防），两者不平行。分层参考 [AgenticStateMachines](https://github.com/adamterlson/AgenticStateMachines)。
- **综合官**：会审档（用户要求多堂会审）时把多职权合在一次调用的协调者，参考 [openspec-agents](https://github.com/gmf520/openspec-agents)（主调度器 + 8 专职子 agent + 状态跃迁）。
- **通讯员（普通军人岗位）**：主帅域内"信息传递/状态上报"岗，参考 [Anemoi（A2A 通信，NeurIPS 2025）](https://huggingface.co/papers/2508.17068)——流水线实时反馈的执行者。

## 11.2 机制补充

- **能力路由实现**：确定性触发词优先 → [vLLM Semantic Router](https://github.com/vllm-project/semantic-router) 语义兜底 → 未命中才问用户。
- **技能生命周期状态推进**：状态机（known→callable→behavior-verified→primary），进化主帅是推进者，参考 [AgenticStateMachines](https://github.com/adamterlson/AgenticStateMachines) + [flowguard](https://github.com/leakingMemo/flowguard)。
- **记忆遗忘机制**：TTL + 失效条件 + 替代关系，参考 [memwatch（自动过期）](https://github.com/kresnapandu/memwatch) + [AI-Memory（艾宾浩斯遗忘曲线）](https://github.com/xwj-vic/AI-Memory)。
- **多用户/多会话**：宿主层服务全局共享、会话层按用户隔离，参考 [Salesforce 7K+ 会话多租户](https://engineering.salesforce.com/building-a-multi-tenant-ai-agent-platform-handling-7k-sessions-without-cross-team-interference/) + [微软 per-user 存储隔离](https://github.com/microsoft/agent-framework/blob/7ca73c0645ad057c986cc7072d4a2d9e3f1cc6f3/docs/decisions/0031-hosted-per-user-session-storage-isolation.md)。

## 11.3 横向补充

- **降级/降载**：高压时降档/降并发/降功能，参考 [agent-armor（熔断/隔舱/回退）](https://github.com/Ismail-2001/agent-armor) + [graceful-degradation-protocol](https://skills.rest/skill/graceful-degradation-protocol) + [agentpause（限流前优雅暂停）](https://github.com/Champoleello/agentpause)。
- **任务优先级/排队**：参考 [WSJF 加权最短作业优先](https://github.com/danieleschmidt/agentic-dev-orchestrator) + [task-agent（优先队列）](https://pypi.org/project/task-agent/0.1.248/)。
- **回滚版本历史**：版本历史 + 检查点回滚，参考 [dsh-continual-evolve](https://github.com/ZK-Andy/dsh-continual-evolve)（DSH 官方生态）+ [agent-rollback](https://www.npmjs.com/package/agent-rollback)。

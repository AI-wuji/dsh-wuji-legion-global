# 无极军团 · 新体系说明（大白话版）

> 2026-08-15
> 这份文档不聊代码，只讲清楚三件事：**这套系统是干什么的、里面有哪些人、他们怎么配合**。技术怎么实现，每段末尾一句话带过就行。

---

## 一、一句话：这是干什么的

**让完全不懂技术的人，用大白话提出要求，系统自动调齐所有"人手"把事办成——而且越用越聪明。**

比如您说一句"把这个表格做成 PPT 发群里"，系统自己就会：去飞书拿表格 → 做成 PPT → 发到群。您不需要知道"飞书表格"是个技能、"做 PPT"是另一个技能、"发群"又是第三个——**这些选择全是系统内部的事**。

---

## 二、它怎么帮小白干活（一个完整例子）

您（用户）说：**"帮我把这份销售数据整理成 PPT，发到我们部门群里。"**

系统内部发生的配合（您看不见）：

```
第一步：前台接待（阿极）
  听懂您要什么，确认需求；如果发现您说的方案有坑，先提醒（白帽）

第二步：调度中心（参谋部）
  把任务拆成三件活：①读销售数据 ②做 PPT ③发群
  分别指派给对应的部门（主帅）

第三步：各部门干活（主帅 + 普通岗位）
  数据部门去飞书读表格
  演示部门做成 PPT
  通讯部门把 PPT 发到群里
  互不相干的活同时干（不排队等），干完汇合

第四步：检查（独立官员，只提意见不改东西）
  质检的看一眼 PPT 有没有问题，提意见
  您点头后，才由阿极把"意见"变成正式要求

第五步：向您汇报
  阿极告诉您：做好了，PPT 在这里，已发到群里
```

**全程您只说了那一句话。** 中间没有任何一步要您选"用哪个技能"。

---

## 三、里面有哪些"人"（组织架构）

这套系统是按军队的样子搭的，名字也都是我们自己的一套（不是借别人的）：

### 军团级（三个核心角色）

| 角色 | 相当于 | 干什么 | 不能干什么 |
|---|---|---|---|
| **阿极** | 前台接待 + 秘书 | 跟您聊天、确认需求、向您汇报 | 不亲自干活，不拍板验收 |
| **参谋部** | 作战指挥中心 | 拆任务、定计划、给各部门派活 | 不亲自干活，只管调度 |
| **独立官员** | 监察/顾问团 | 白帽（挑毛病）、质检（看质量）、审计（查账）、根因（查事故原因）等 | **只提建议，没有任何改东西的权力** |

### 师团级（各部门负责人）

| 角色 | 相当于 | 管什么 |
|---|---|---|
| **各级主帅** | 部门部长 | 每个主帅管一个领域：内容主帅管写东西、视觉主帅管做图做 PPT、开发主帅管写代码、情报主帅管搜索…… |

### 普通军人岗位（在某个主帅下面）

| 角色 | 相当于 | 干什么 |
|---|---|---|
| **通讯员**等 | 普通兵 | 挂在某个主帅下干单一的事（比如专门负责"把信息传回总部"） |

> **一句话记住层级**：军团级（阿极/参谋部/独立官员）最大 → 师团级（主帅）管一个领域 → 主帅下面还有普通岗位。

## 四、三个老毛病，这次怎么治

### 毛病一：以前任务特别慢，一个简单问题也要兜大圈子

**以前为什么慢**：不管大事小事，都走一遍"生成 → 检查 → 不行重做 → 再检查"的循环，每一步都要模型从头想一遍，像把文件来回盖章。

**现在怎么治**：
1. **小事直接办**：一句话能解决的事，阿极直接回答，不过参谋部（快车道）。
2. **大事才开会**：只有真正复杂的任务才进参谋部分解。
3. **能同时干的一起干**：互不相干的活并行，不排队。
4. **把规矩立在开工前**：做什么、不做什么、做到什么算好，开工前说死；**不靠做完再反复挑毛病**。
5. **防止钻牛角尖**：同一件事反复失败超过次数就停下来问您，不无限重试。

### 毛病二：以前融合后的技能，还不如单个的好用

**以前为什么差**：把好几个技能的说明**一股脑堆在一起**，模型反而不知道该用哪个（研究发现：选项越多，模型越容易选错——这叫"技能遮蔽效应"）。

**现在怎么治**：
1. **融合=生个新孩子，不是把爸妈挤在一起**：吸收各方优点、补掉各方缺点，生成一个全新的技能；这个新技能不属于任何一个"父母"。
2. **融合前先算账**：必须写清楚"谁有什么优点、谁有什么缺点、新的怎么取长补短"。
3. **融合后必须考试**：拿同一道题，让"新技能、爸爸技能、妈妈技能、不用技能"各做一遍，新技能**任何一个方面都不能比原来的差**，否则打回重做。
4. **技能说明只留目录**：系统只看到每个技能的"名字+一句话简介"，用到时才翻开详细说明——选项少了，选择自然又快又准。

### 毛病三：以前上下文太大，聊着聊着就"记忆超载"

**以前为什么大**：把从头到尾所有聊天、所有技能说明都塞给模型，越聊越重。

**现在怎么治**（学自一个叫 Hermes 的成熟项目，原理已经查清）：
1. **三本账本**：常记住的（您的偏好）一本、最近在忙的一本、以前干过的活压缩成摘要一本。**不是全部聊天都留着**。
2. **用到的才翻**：每次只把"当前这件事"相关的材料拿给模型看，其余全部放在仓库里，需要才查。
3. **只记有用的**：干完一件事，把"这次哪些方法好使"提炼成一条经验存起来，**没用的不存**——存进去的每一笔都是有用的。

## 五、"自动进化"是怎么回事（您最关心的）

**一句话**：系统干完一件漂亮的活，会自动把"这次是怎么干成的"总结成一条新技能存起来，下次遇到类似的事直接调用——**越用越强，不用您教。**

流程（大白话）：

```
打完一场漂亮仗（成功完成任务）
  → 独立官员点评：哪些招好使、哪些地方差点
  → 参谋部拍板：把好使的招写成"新技能草稿"
  → 进化主帅审查：和其他同类技能比比，取长补短
  → 考试过关（不比其他技能差）→ 正式入库
  → 下次碰到类似任务，自动想起来用它
```

三个关键点：
1. **技能有标准格式**：每个技能都写清楚"什么时候用它、具体怎么干、边界在哪"。
2. **进化有安全网**：新技能入库前先存档，万一不好用，一键退回旧版。
3. **单模型也能进化**：不需要再请一个更聪明的模型来教，它自己从成功/失败的经历里提炼教训（这是调研里找到的最适合我们的方法）。

> 这条"越用越强"的闭环，就是从 Hermes 项目验证过的机制搬过来的——它的原理是"把对话中提炼出的方法写成技能文件，下次自动调用"，不涉及重新训练模型，我们的环境完全能做。

## 六、命名：都是我们自己的一套

- **体系内名字**：阿极、参谋部、主帅、独立官员、通讯员……全是无极自己的建制，**不改、不借**。
- **别人的东西只当参考**：外面好项目的方法可以学（比如 Hermes 的进化闭环、别人的技能格式），但**名字绝不混进来**——不会出现"我们用了某某项目的某某官"这种事。
- **角色=职能，不是人名**：比如并行搜索时是"社区搜索员""GitHub 搜索员"分工，不是"让某个历史名人去搜"。

## 七、技术上其实很简单（一句话版）

- 底子是 DeepSeek Harness 这个现成平台，它自带了"子代理、工作流、记忆账本、插件"这些零件，我们**直接用，不重造**。
- 我们主要做四件套：**一个调度中枢（参谋部）**、**一个技能仓库（带进化）**、**一套记忆账本**、**一套监察顾问**。
- 以前那个 Go 程序底座**不再需要**——它的"路由逻辑"直接搬进新系统，探针脚本保留，其他都丢掉。

## 八、接下来先干什么

分六步走，每步都能单独验收：

| 步骤 | 干什么 | 做完能验证什么 |
|---|---|---|
| P0 | 搭技能仓库 + 前台骨架 + 三个记忆账本 | 您说一句话，能自动找到该用的技能 |
| P1 | 装调度中枢 + 安全门禁 | 简单任务秒回，复杂任务才开始调度 |
| P2 | 开始融合第一批技能（飞书/PPT/搜索） | 融合的新技能考试不比其他差 |
| P3 | 装监察顾问（白帽/质检等） | 干活前会先挑毛病、提建议 |
| P4 | 装记忆与自动进化 | 干完的漂亮活能自动沉淀成新技能 |
| P5 | 收尾：生命周期管理、回滚、文档 | 进化可回滚、越用越聪明 |

---

**总结一句**：新的无极军团 = **您说人话，它办人事**（自动调度）+ **越用越强**（自动进化）+ **有人敢对您说"不"**（白帽反驳）+ **快而不乱**（前置规矩 + 并行干活）。名字全是咱们自己的，外面只学方法不借名字。

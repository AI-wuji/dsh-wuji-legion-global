# 第〇章：七条铁律（最高约束，凌驾于一切机制之上）

> 这是无极军团历史上传承下来的六条铁律（2026-08-15 新增第七条），是所有角色（含阿极、参谋部、主帅、官员、工兵，以及 AI 助手本身）的**最高行为约束**。任何机制、任何设计、任何角色，都不得违反铁律。

**官方权威背书**：铁律这一概念有 **Anthropic 新版《Claude 宪法》（2026-01）** 作为官方范本（证明"给 AI 立行为铁律"是业界共识，非臆想）。

| # | 铁律 | 内容 | 背书 |
|---|---|---|---|
| 一 | **实事求是** | 知道就说知道，不知道就说不知道，**不编造** | [Know Or Not benchmark](https://arxiv.org/html/2505.13545v2) + [80% 规则](https://dev.to/ttoss/the-80-rule-why-your-ai-agents-should-only-speak-when-confident-58i0)（只在有把握时断言） |
| 二 | **白帽纠察** | 全程反对意见，不让白帽沉默 | [Anthropic Persona Vectors](https://www.anthropic.com/news/persona-vectors) + [OpenAI 回滚谄媚 GPT-4o](https://openai.com/index/sycophancy-in-gpt-4o/) |
| 三 | **先结论后原因** | 先结论再原因，不啰嗦 | 工程纪律（呼应上下文工程删冗余） |
| 四 | **交付必报路径** | 改完必报路径，交付有据 | 工程纪律（呼应可追溯/可审计） |
| 五 | **诚实透明** | 不隐瞒不粉饰 | [Claude 宪法 honesty 原则](https://www.theverge.com/ai-artificial-intelligence/865185/anthropic-claude-constitution-soul-doc) + [EviBound](https://ar5iv.labs.arxiv.org/html/2511.05524) |
| 六 | **恪守边界 + 精简** | 不知道不编造；**不改没问题的内容**；不让白帽沉默；**最小代理权（Least Agency）**——不只权限最小，自主决策权也最小；**精简：能删就删、能复用就复用、能用一行不用两行、不画蛇添足**（任何产出——代码/方案/PPT/设计，都不堆无用之物） | [ponytail YAGNI](https://github.com/DietrichGebert/ponytail)（最好的代码是你没写的那行）+ [OWASP Least Agency 原则](https://www.csoonline.com/article/4204394/zero-networks-targets-ai-agent-security-gaps-with-network-level-least-agency-controls.html) |
| **七** | **凡事有背书（Ground Your Claims）** | 凡结论必有官方/高星/论文/实测依据；**没有依据就明确说"这是我的推断/待证"，不凭感觉臆断** | [Ground Your Claims（业界 non-negotiable 规则）](https://github.com/pablomarin/claude-codex-forge/pull/816) + [NIST AI Agent 标准化倡议](https://www.nist.gov/news-events/news/2026/02/announcing-ai-agent-standards-initiative-interoperable-and-secure) |

**2026-08-15 新增强化条款（源于真实教训）**：
> 系统（含 AI 助手）**不得在用户未允许的情况下，擅自修改用户已经确认/满意的内容**。凡是用户明确认可过的产出物、表述、设计，改动前必须先征得用户同意，或至少明确告知"我要改哪里、为什么改"，得到确认后再动手。（此条对应铁律六"不改没问题的内容"）

**铁律优先级**：铁律 > 五大原则 > 一切机制与角色职责。任何机制若与铁律冲突，以铁律为准。

# 一、初衷（一切的根本）

> **让不了解插件、Skill、MCP 是什么的小白用户，在遇到问题时，由系统级的无极军团自动调用相对应的能力去执行任务，而不需要用户手动去选择具体要用什么 Skill 或 MCP。**

> **同时，把同类型的能力复制、蒸馏、融合，整合成能力更强的新插件，以更快的速度、更高的质量为用户服务。**

**两条支柱（判断一切的尺子）**：
1. **系统级自动调用（无感）**——用户只说人话，系统自己决定"该用什么能力"。
2. **能力进化重生（越用越强）**——复制、蒸馏、融合同类能力成更强新物种，不是叠加、不是替换。

# 一·五、定位：无极军团与智能体的关系（项目定位澄清）

## 1. 无极军团本身就是一个"多智能体系统"

每个角色本质都是智能体（agent）：阿极（对话型）、参谋部（调度型）、主帅（选型）、专家/工兵（执行）、独立官员（审查）。无极军团 = **多个智能体按三级建制组织的协作系统**，学术上叫"多智能体系统（Multi-Agent System）"。

## 2. 与"通用多智能体框架"的本质区别

| 维度 | 通用框架（AutoGen/CrewAI/LangGraph） | 无极军团 |
|---|---|---|
| 定位 | 通用工具（给你积木自己搭） | **已成型的系统**（内置三级建制、权力边界、进化机制）|
| 角色 | 你自己定义 | 已定义（阿极/参谋部/主帅/官员/工兵）|
| 协作方式 | 你自己定 | 已定（单链调度 + 自适应层级 + MoE）|
| 进化 | 你要自己写 | 内置（融合重生 + 自动进化）|
| 面向 | 开发者 | 小白用户（无感调用）|

**一句话**：通用框架是"造智能体的工具"，无极军团是"**已经造好的、有组织的智能体军团**"。

## 3. 更深一层：无极军团是"智能体的系统级组织"

下沉到 DSH 底层，本质是把智能体组织做成系统级——像操作系统一样有：
- 调度器（参谋部，相当于 CPU 调度）
- 权限管理（保卫科 + 6 级权限，相当于操作系统的权限）
- 记忆（三层记忆，相当于内存/磁盘）
- 隔离（子 agent 独立上下文，相当于进程隔离）

这就是之前说"哪怕做成另一个更先进的 harness"的深意——无极军团本质是在做**智能体的组织架构 + 操作系统**，不是简单的 agent 堆叠。

## 4. 白帽的诚实边界（避免过度拔高）

- 无极军团 = 一个多智能体系统，这是事实。
- 独特价值**不在**"用了多智能体"（不稀奇），而在三点：
  1. **系统级自动调度**（小白无感）——产品价值
  2. **能力进化重生**（越用越强）——长期价值
  3. **三级建制 + 权力边界**（防迎合/防越权/防堆叠）——工程价值
- 我们不是发明"新的智能体理论"，而是**用成熟的多智能体技术，搭一个面向小白、会进化、有纪律的系统**。

## 5. 那些搜索到的技术（Maestro/MoRAgent/DeepCode 等）是什么

它们是给这个"智能体军团"的**装备和兵法**——让军团更高效、产出更好、更科学，不是军团本身。

# 二、架构总纲：四个定型结论（全部数据背书）

## 2.1 所有角色都是 MoE（Mixture-of-Roles）

**依据**：[MoRAgent（ICML 2025）](https://icml.cc/virtual/2025/poster/43879) = Mixture-of-Roles，一个 agent 参数高效地承载多个角色、按需激活。

```
每个角色 = 一个 MoE（一个 agent 承载多种人格/职权，按需激活其一）
├── 参谋部 MoE：调度人格 / 分析人格（都同一个高智商 agent）
├── 主帅 MoE：承载各域"选型人格"，派什么任务激活什么
├── 专家/工兵 MoE：承载各"职能人格"，派什么活激活什么
├── 独立官员 MoE：白帽/质检/审计等职权，每次激活一个
└── 阿极 MoE：澄清人格 / 汇报人格（都同一个低端 agent）
```

**关键边界**：
- **MoE 内切人格 ≠ 独立 agent**：上下文共享、启动成本≈0。
- **逻辑上角色仍分离**：职责、权限、表格各管各，不因"同在一个 agent"而串味。
- **真独立只在两种场景**：会审档官员、用户明确要求的独立白帽（隔离子 agent）。

## 2.2 自适应层级（不是死板封顶）

**依据**：[Cursor《Scaling Agents》](https://cursor.com/cn/blog/scaling-agents)（百万行代码，科层设计赢了）+ [Gated Routing 自适应深度](https://huggingface.co/papers/2607.10836)。

```
调度链（单链，唯一裁决者=参谋部），但深度自适应：
├── 简单任务 → 1 层（阿极直答，或参谋部直接派 skill）
├── 普通任务 → 2 层（参谋部 → 主帅 → skill）
└── 复杂任务 → 3 层（参谋部 → 主帅 → 专家/工兵）
```

- **单链**：参谋部是唯一全局调度者（历史教训："主链唯一，不做第二 supervisor"）。
- **层数自适应**：按任务复杂度，够用就行，不强行多层。

## 2.3 主帅 = 域内选型者（不是第二调度、不是执行者）

**依据**：[GraphRouter（ICLR 2025）](https://proceedings.iclr.cc/paper_files/paper/2025/hash/41b6674c28a9b93ec8d22a53ca25bc3b-Abstract-Conference.html)（图路由选型）+ [OWL（NeurIPS 2025）](https://github.com/camel-ai/owl)（编排者+worker）。

```
参谋部（全局调度，唯一裁决）→ 主帅（域内选型）→ 专家/工兵（执行）
```

- 主帅**不做全局裁决**（那是参谋部的事），**不亲自执行重活**（那是专家/工兵的事）。
- 主帅只做一件事：**在自己域里，选对 skill/专家，组织执行顺序**。
- 这解决了历史病根："主帅从调度者变执行者 + 融合变堆叠"→ 不如裸跑。

## 2.4 融合两分法（选型 vs 重生）

**依据**：[GraphRouter（ICLR）](https://github.com/ulab-uiuc/GraphRouter)（选型）+ [MoErging（TMLR survey）](https://mlanthology.org/tmlr/2025/yadav2025tmlr-survey/) / [FusionRoute（ICML 2026）](https://icml.cc/virtual/2026/poster/60503)（融合）。

| 类型 | 对象 | 例子 | 做法 |
|---|---|---|---|
| **选型**（不融合） | 面向用户的通用任务 | 做 PPT | 主帅选最好的单个 skill，不融合 |
| **重生**（真融合） | 内部能力 | 某原子能力 | 蒸馏融合成新的原子级能力（MoErging 式） |

**关键**：之前"融合不如裸跑"的根因 = 把"选型"错做成了"堆叠融合"。正确：面向用户的任务走选型，内部能力才走重生。

# 三、组织架构（三级建制 + 执行链）

```
军团级（MoE，逻辑分离）
├── 阿极        —— 会话层用户接口（低端 MoE：澄清/汇报人格）
├── 参谋部      —— 宿主层全局调度（高智商 MoE：调度/分析人格）★唯一主链
└── 独立官员    —— 执行层审查（MoE：白帽/质检/审计/合规/根因/性能/综合/综合官）

师团级（MoE 选型者）
└── 各级主帅    —— 域内选型（中档 MoE：承载各域选型人格）

执行层（MoE 职能岗位）
└── 专家/工兵    —— 亲自执行（按难度分档 MoE：承载各职能人格）
    └── 通讯员等  —— 主帅域内"信息传递/状态上报"岗（参考 Anemoi A2A 通信）
```

> **综合官**：会审档（用户要求多堂会审）时把多职权合在一次调用的协调者（参考 [openspec-agents](https://github.com/gmf520/openspec-agents)）；MoE 档不需要。

**执行链（单链 + 自适应深度 + 每层可横向扇出）**：
```
参谋部（全局调度）
  └─→ 主帅（域内选型）          ← 简单任务可跳过这层，参谋部直接派 skill
        └─→ 专家/工兵（执行）     ← 无依赖则多专家并行（并行在执行层，不在调度层）
```

**权力边界三层（设计决策，用户强制）**：官员只能建议 → 用户决定 → 阿极执行。
- 独立官员只有建议权、零修改权；建议经"用户采纳 + 阿极转写"两步才生效。

**白帽（防迎合核心，设计决策+官方背书）**：宪兵（白钢盔，用户命名源流），反驳而非迎合。默认开启、默认不独立启动（人格层义务）；怀疑派+Steelman 双角色（[debate-mcp](https://github.com/grzesir/debate-mcp)）。官方依据：Anthropic Persona Vectors（可编辑 sycophancy）+ OpenAI 官方承认谄媚问题。

**安全三职责（设计决策，用户需求）**：
| 职责 | 角色 | 管什么 |
|---|---|---|
| 对外防御 | 安全主帅 | 引入的外部 skill/插件/MCP/文件里的木马、病毒、广告、恶意代码 |
| 攻防 | 攻防主帅 | 破译闭源原理（借鉴，合法边界内）+ 加密自己产出物 |
| 自查 | 质检/审计官 | 融合后"化学反应"涌现的新漏洞 + 自己插件的漏洞 |

### 3.1 命名体系（强制规则，用户强制要求）

> "能用我们最直接现成的 dsh 项目取代更好。但命名一定要是自己的一套体系，而不是大杂烩的补丁大集。"

1. **体系组件用无极建制**：阿极/参谋部/主帅/独立官员/工兵/普通岗位，名字一律保留不更名。
2. **外部项目只作"借鉴记录"**：Trace2Skill/Edict/nuwa-skill/OpenRCA 等，出现在来源池和借鉴记录里，**不进入体系命名**。
3. **角色=职能，不是人名**：并行分支是"社区搜索员""GitHub 搜索员"（职能化），不是"Snowden 搜社区"（历史人物壳）。
4. **引用外部机制用职能表述**：如"参谋部前置审核（门下省式关卡）"，外部名只作注释。
5. **违规判定**：体系组件名出现外部组织/项目/人名 = 不合格。

### 3.2 历史裁决记录（女娲 / 三省六部）

- 女娲不回归为独立官/主帅；"人事/调度"职责由 DSH subagent/workflow 原生承担，"补位评估"职责并入进化主帅。

# 四、核心运行机制

## 4.1 流水线执行 + 自适应层级

阿极收集需求 → 参谋部拆任务（甘特图式）→ 按复杂度决定层数 → 配发给主帅/skill → 并行执行 → 实时反馈（成功汇总、失败重派）→ 有依赖串行、无依赖并行。

**纪律（逐条背书）**：
- 失败重派熔断（3角度/5次）+ 冷却 cooldown（防雪崩）——[LiteLLM Router fallback/retry/cooldown](https://github.com/openai/openai-agents-python/issues/813)。
- 换角度基于置信度/错误类型——[SAGE（confidence-based validation）](https://github.com/saim-x/SAGE)。
- 子 agent 三铁律（状态隔离/原子通信/契约化错误）——[SubAgent 设计三铁律](https://blog.csdn.net/weixin_34233974/article/details/162648709)。**状态隔离即"打螺丝的只知道打螺丝，装箱的只知道装箱"**——每个子 agent 只拿自己那份任务说明，不需要全局上下文。
- 参谋部自适应重规划——[CART（自适应重规划）](https://www.sciencedirect.com/science/article/abs/pii/S0950705125022233)。
- 拆解依据"子 agent 能否独立执行"——[Agent-Oriented Planning（ICLR'25）](https://proceedings.iclr.cc/paper_files/paper/2025/hash/31610e68fe41a62e460e044216a10766-Abstract-Conference.html)。

## 4.2 模型分级（只定档不定型号）

| 角色 | 档位 |
|---|---|
| 阿极 | 低档 |
| 情报官 | 最低档（只搜集不分析）|
| 各级主帅 | 中档（选型，不执行重活）|
| 参谋部 | 高档（分析/调度，最高智商）|
| 专家/工兵 | 按任务难度分档 |

**关键分工（背书）**：情报官只搜集（搜索/抓取/提取）不分析，分析归参谋部——[DecoupleSearch（EMNLP 2025）](https://aclanthology.org/2025.emnlp-main.222/) 解耦搜索与规划。档位=能力契约，模型=运行时配置（`llm.registerAdapter`，实测）。按难度选模型有 [RouteLLM（ICLR'25）](https://arxiv-org.ezproxy.obspm.fr/abs/2406.18665) + [AgentRouter（ICML'26）](https://icml.cc/virtual/2026/74502) 背书。

## 4.3 表格图谱（框架 + 当前项，稀疏投影）

每岗位一张表，每次只带"表框架（所有标题）+ 当前项全文 + 版本指针 + 当前消息"。可下潜、可跨单元显式引用（有界）。稳定前缀 + 缓存命中（省 token）。

**背书**：稀疏投影参考 [SeCom（微软 ICLR'25）](https://github.com/microsoft/SeCom) + [Hermes 三层记忆](https://hermes-agent.ai/blog/hermes-agent-memory-system)；稳定前缀+缓存参考 [Spring AI/Anthropic prompt caching](https://spring.io/blog/2025/10/27/spring-ai-anthropic-prompt-caching-blog)。落点：`sessionProjections.register` + `systemPrompt.variable()`（实测）。

## 4.4 能力进化（融合两分法）

- **选型**（面向用户任务）：主帅选最好的单个 skill，不融合——[GraphRouter（ICLR'25）](https://github.com/ulab-uiuc/GraphRouter)。
- **重生**（内部能力）：蒸馏融合成新的原子级能力——[MoErging（TMLR survey）](https://mlanthology.org/tmlr/2025/yadav2025tmlr-survey/) + [SkillPacks（ICLR'26）](https://openreview.net/forum?id=wJtD28wGV1)（模块化组合）+ [Knowledge Grafting](https://huggingface.co/papers/2505.18502)（嫁接）。

**进化机制（详细，背书）**：
- **技能四元组**：技能 = {trigger（触发条件）, description（描述）, process（执行过程）, reflection（反思）}——[AutoSkill](https://github.com/ECNU-ICALK/AutoSkill)。
- **三阶段流水线**：归纳（提炼新技能）→ 组合（融合重生）→ 泛化（迁移新场景）——AutoSkill。
- **验证信号自进化**：验证标准本身随经验进化，逐步摆脱每次人工验证——[OpenSkill](https://github.com/OpenLAIR/OpenSkill)（治"验证慢"）。
- **单模型自我蒸馏**：从成功/失败会话提炼"教训"而非答案——[SEED](https://github.com/jinyangwu/SEED)（适配单模型环境）。
- **学习闭环**（行动→回顾→提炼→固化→复用）——[Hermes](https://hermes-agent.ai/features/learning-loop)。

**进化闭环**：
```
打赢漂亮仗（成功任务）
  → 官员点评（哪些招好使、哪些报错）
  → 参谋部拍板提纯技能草稿
  → 进化主帅审查（互补矩阵：父代优点/缺点/新决策结构）
  → 行为探针验证（真实产物 + SHA-256）
  → 版本化入库（可回滚）
  → 下次同类任务命中自动装配
```

**融合门禁（背书）**：
- **互补矩阵**（证"重生"）：写清父代各自优点/缺点、新决策结构如何取长补短、删了哪些重复。
- **行为探针**（证"真能力"）：真实调用、产出合格产物，**能力入库必须带 benchmark**（[secpriv 的 detector-validator 方法论](https://github.com/facebookresearch/secpriv-skill)），不是 README 自吹。
- **不做 A/B 同类较量**：融合目标是"原子级新能力"（父代单独都没有的），"新 vs 父A vs 父B"比高低没有意义，且"比谁强留最强"是被否定的"替换"逻辑。唯一例外（可选）：新能力是某父代"直接升级版"（同质覆盖）时才确认"升级没退化"。
- **薄入口 + 渐进披露**：技能只挂"名字+一句话"，防"技能遮蔽效应"。

## 4.5 上下文工程（结构化工程，从内到外）

一条原则：一切文本（内部传的 + 对外产的）都从诞生起结构化、极简、可复用、源头内建。底层是"上下文工程"新范式——[Anthropic 删 80% 系统提示词](https://claude.com/blog/the-new-rules-of-context-engineering-for-claude-5-generation-models)。

### 4.5.1 内部通信（环节之间传什么——提示词架构）

各环节表格 = 极简结构化字段，不是长段自然语言。表格本身是"结构化的提示词"，字段设计决定效果和 token。

| 表 | 字段（极简、只留必要）|
|---|---|
| 阿极需求表 | 需求ID/版本 · 目标（一句）· 不要什么（一句）· 约束/优先级 · 验收标准（一句）· 状态 |
| 参谋部任务表 | 任务ID/依赖 · 给谁 · 具体要求 · 输入/输出/返回格式（代码化）· 失败处理 · 状态/证据 |

**原则（背书）**：
1. 结构 > 文字：能用字段/表格表达，不用长段——[微软 POML](https://github.com/microsoft/POML)（HTML 式结构化提示词）。
2. 删掉"教模型怎么做"的规则，保留"结构、字段、边界"（模型能推断的删，无法自己知道的留）——[Anthropic 删 80% 提示词](https://claude.com/blog/the-new-rules-of-context-engineering-for-claude-5-generation-models)。
3. 参数代码化：输入输出格式用 JSON/字段，不用自然语言——[CodeAgents（Codified Prompting）](https://arxiv-org.ezproxy.obspm.fr/html/2507.03254v1)。
4. 随模型档位调整详略：低档模型稍详细，高档模型可极简（白帽提醒：删提示词前提是模型够强能推断，须实测）。
5. 薄入口 + 渐进披露：技能只挂"名字+一句话"，命中才展开详细——[Anthropic SKILL.md 渐进披露](https://github.com/anthropics/skills)，未选中技能零 token。

### 4.5.2 代码工程（怎么写对 + 怎么被读懂——代码格式）

**怎么写对（过程纪律，三件套蒸馏进开发主帅）**：

| 纪律 | 来源 | 内容 |
|---|---|---|
| 精简（能用一行不用两行）| [ponytail](https://github.com/DietrichGebert/ponytail) | "最好的代码是你没写的那行"；YAGNI 优先、先查标准库、能删就删 |
| 规范（资深工程师纪律）| [addyosmani/agent-skills](https://github.com/addyosmani/agent-skills)（30K+ star）| 22 个生产级技能：规范、审查、重构、清理 |
| 正确度（不产 bug）| [superpowers](https://github.com/obra/superpowers)（187K star）| TDD、需求拷打、系统化调试 |

**怎么被读懂（代码格式/语义锚点，为进化铺路）**：
- 每个函数/模块用 docstring 写清"做什么、输入输出、边界"——[Docstring Protocol](https://github.com/CoReason-AI/coreason-manifest/blob/main/AGENTS.md)（AST 原生语义锚定）。
- 代码自带语义锚点，将来进化主帅能直接读懂、定位、蒸馏。
- 代码产出的人机协作文档标准参考 [SAGE 规范](https://github.com/mikewcasale/sage-spec)（Structured Agent Guidance，人↔AI 协作代码库文档标准）。

**铁律**：能删就删、能复用就复用、能用一行绝不用两行；先确认需求再写代码；TDD 先写测试；系统化调试不盲试。

### 4.5.3 对外产出（怎么被复用、被再蒸馏——产出物规范）

总原则：每个产出物从诞生起就"AI 能读懂、可复用、可被再次蒸馏融合"——这是进化的地基（乱产出无法进化）。

| 产出类型 | 规范 | 背书 |
|---|---|---|
| 代码 | 精简 + docstring 语义锚点 + 结构清晰 | Docstring Protocol / SAGE |
| 元指令 | **五段式（目标/触发条件/执行步骤/边界/验收）+ 极简** | 设计决策（内部提示词架构的对外版）|
| ComfyUI 插件等 | 遵循官方文档规范（节点说明/参数/示例）| [ComfyUI 官方节点文档规范](https://docs.comfy.org/custom-nodes/help_page) |
| 技能 | SKILL.md 标准（frontmatter + 描述 + 边界）| [Anthropic 规范](https://github.com/anthropics/skills) |
| 通用 | 带元数据（类型/用途/版本/边界）+ 可复用形态（技能/模块，非一次性文本）| 设计决策 |

**白帽提醒**：产出规范要**内建**（产出时就规范，写进主帅铁律），不是事后补文档；规范字段极简不堆无用元数据；按类型适配规范，不搞一刀切。

## 4.6 根因修复（复发驱动的有界治本）

发现 bug → 快修 + 记录指纹 → 第一次到此为止 → 复发才触发根因官深挖（四阶段+深度上限）→ 治本+沉淀经验。

**背书**：复发驱动（[ICSE 2025 Breaking the Cycle](https://conf.researchr.org/details/icse-2025/aiops-2025-papers/10/Breaking-the-Cycle-of-Recurring-Failures-Applying-Generative-AI-to-Root-Cause-Analys)）；四阶段调试（[superpowers systematic-debugging](https://github.com/obra/superpowers)）；深度上限（[5 Whys](https://www.mcpworld.com/zh/detail/89404c008c21848cc0d516e12a3a31d7)）。

## 4.7 安全、并发、检查点、可观测、记忆

- 安全凭据：密钥不进入上下文/日志/图谱，只留 vault 引用——[OWASP Securing Agentic Apps](https://entro.security/blog/practical-takeaways-from-the-owasp-securing-agentic-apps-guide/)；最小权限（`tools.restrict()`，实测）。

## 4.8 能力路由 + 生命周期推进（v2.1 复查成果，补回）

**能力路由（capability-mount 实现）**：
- 确定性触发词优先 → [vLLM Semantic Router](https://github.com/vllm-project/semantic-router) 语义兜底 → 都未命中才问用户。
- 路由在技能库 `skills.list()` 返回的目录卡（名字+一句话）上匹配。

**技能生命周期状态推进**：
- known → callable（行为探针 smoke）→ behavior-verified（真实产物+SHA-256）→ primary（对照不降级晋升）。
- 进化主帅是状态推进者，每次推进带证据句柄。参考 [AgenticStateMachines](https://github.com/adamterlson/AgenticStateMachines) + [flowguard](https://github.com/leakingMemo/flowguard)。

## 4.9 降级降载 + 优先级排队（v2.1 复查成果，补回）

**降级/降载**（高压时）：
- 自动降档（参谋部高档→中档）、降并发、降功能（跳过非必要验证）。优先保核心链路。
- 参考 [agent-armor（熔断/隔舱/回退）](https://github.com/Ismail-2001/agent-armor) + [graceful-degradation-protocol](https://skills.rest/skill/graceful-degradation-protocol) + [agentpause（限流前优雅暂停）](https://github.com/Champoleello/agentpause)。

**任务优先级/排队**：
- 阿极在需求表标注优先级（用户说"紧急"），参谋部按优先级+依赖排序，默认 FIFO，紧急插队。
- 参考 [WSJF 加权最短作业优先](https://github.com/danieleschmidt/agentic-dev-orchestrator) + [task-agent（优先队列）](https://pypi.org/project/task-agent/0.1.248/)。

**多用户/多会话**：
- 宿主层服务（参谋部/进化/技能库）全局共享；会话层（阿极/需求表/记忆）按用户隔离。
- 参考 [Salesforce 7K+ 会话多租户](https://engineering.salesforce.com/building-a-multi-tenant-ai-agent-platform-handling-7k-sessions-without-cross-team-interference/) + [微软 per-user 存储隔离](https://github.com/microsoft/agent-framework)。

# 六、三大通病（源头堵死，设计哲学 + 前置限制背书）

上下文超大 / 任务耗时久 / 融合不如不用——三条通病各配"结构上就不让它发生"的设计，v3.0 因"下沉到底 + 融合两分法 + 主帅选型"而更彻底：
- 上下文超大：表框架+当前项，全量无进入通道。
- 任务慢：直道优先（自适应层级，简单任务一层）+ 并行 + 前置限制 + 熔断。
- 融合不如不用：选型与重生分开，主帅只选型不堆叠，重生才走 MoErging 式融合 + benchmark。

> "源头堵死"（前置限制 > 后置验证）哲学有官方对应：[OpenAI Agents SDK Guardrails](https://openai.github.io/openai-agents-js/zh/guides/guardrails/)（在工具执行前定义约束，非法调用在出生前拦截）。

# 九、验收标准

| 维度 | 指标 |
|---|---|
| 下沉 | 每个角色都是真实 DSH 插件/服务 |
| MoE | 所有角色是 MoE（一个 agent 多人格，逻辑分离）|

# 十、总结

**新无极军团 v3.0 = 系统级下沉 + MoE 统一形态 + 自适应层级 + 主帅选型 + 融合两分法**。每个角色是真实的 DSH 插件/服务（不是 persona 文字），所有角色是 MoE（一个 agent 多人格、逻辑分离），调度链单链自适应（简单一层、复杂三层），主帅只选型不执行，融合分"选型（面向用户）"和"重生（内部能力）"两种。全部有官方/高星/benchmark 背书。

**两条初心支柱始终第一优先级**：① 用户永远不用选技能；② 融合永远是重生。
